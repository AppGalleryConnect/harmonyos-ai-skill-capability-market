# CH2026032801249-内置文本的组件文本样式优化

## 来源与版本

身份：扫描Rule ID CH2026032801249。变更版本：26.0.0 Beta1。

[完整官方章节](../../changelogs/26.0.0/beta1-ux-style-and-effect-changes.md#内置文本的组件文本样式优化)（起始行87）；[官网原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/changelogs-ux-7001#ch2026032801249)。接口起始版本、行为版本与target隔离分别核对，不相互替代。

## 旧新行为

target≥26.0.0时，官方清单中内置文本组件的孤字换行、小语种行高及音节换行规则发生变化。系统语言与应用文案语言是两项事实，应用显示中文不排除小语种系统下行高变化。

## 影响条件与工程核查

按官方完整组件清单核对真实API/重载和内置文本，不能把所有普通Text/Button混入。检查系统语言、文本长度、固定宽高、最大行数和辅助显示设置，沿封装核对实际布局约束。

## 受影响与不受影响示例

受影响：系统切为藏语/缅甸语，内置文本行高变化与固定高度形成裁切，或孤字换行使现有布局溢出。无需修改：准确组件/条件未命中，或已有充分证据表明布局满足业务；仅短中文文案、未设置属性或构建通过均不足以直接排除。

普通@Extend(Text)中的height(14)不自动属于本条清单内组件的内置文本。先核实它是否实际约束清单组件；没有关联时本条无需修改，其他布局风险单列待核实，不能以行高可能变化推成必须修复。反过来，清单内组件的整体固定高度也可能约束文本，不能仅以“是组件高度而非文本高度”排除裁切。

## 最小方案与边界

已证实局部裁切时调整相关约束或文本布局，保留内容和交互；不统一固定行高、截断文本或关闭全部文本优化消除命中。业务接受新布局仍需有对应判断依据，不把拒绝修改当作无需适配。

## 验证与证据缺口

相关系统语言下覆盖代表性长短内容、换行、行高、按钮命中及周边布局。缺设备、真实内容或布局证据时区分静态风险和待验证范围，不伪造视觉结论。
