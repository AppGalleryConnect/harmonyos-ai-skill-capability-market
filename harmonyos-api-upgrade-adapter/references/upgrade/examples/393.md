# 393-bindSheet在2in1设备中默认避让窗口安全区

## 来源与版本

身份：扫描Rule ID `393`。

[完整官方章节](../../changelogs/6.0.0(20)/beta1-ux-style-and-effect-changes.md#bindsheet在2in1设备中默认避让窗口安全区)位于6.0.0(20) Beta1，明确targetSdkVersion≥6.0.0(20)生效；本地标题映射确认RuleID为393。bindSheet起始API11与行为门槛20分开记录。

本机SDK26.0.0.105 Release的 `ets/component/common.d.ts` 核实bindSheet、SheetOptions和CENTER/BOTTOM；`ets/api/@ohos.window.d.ts` 声明 `Window.getWindowAvoidArea(type: AvoidAreaType): AvoidArea`（since9），有窗口状态及类型限制。`expandSafeArea(...)` 返回组件属性链并控制布局/绘制扩展，它不是安全区数值查询接口。

## 旧新行为

本条是2in1设备自由窗口标题栏为悬浮标题栏时，半模态面板默认避让标题安全区。设窗口高度H、窗口安全区高度S，单位统一为vp：居中面板最大高度由0.9H变为 `H - 2 × (S + 8vp)`；底部面板由 `H - 8vp` 变为 `H - (S + 8vp)`。这里是最大高度规格，不保证所有短内容面板实际等于最大值。

不要忽略悬浮标题栏条件，也不要扩展到所有设备、所有弹窗或所有窗口模式。跟手样式不直接套用这两条公式。

## 影响条件与工程核查

核实设备类型、自由窗口模式、标题栏类型、target及实际面板样式；继续读builder的固定高度/百分比高度、maxHeight和父子布局约束，找是否复制了0.9H或H-8vp的旧上限。检查内容撑满、滚动、底部留白/裁剪及业务是否原本只需要内容自适应高度。

窗口安全区与窗口高度必须来自同一窗口、同一单位和有效状态；getWindowAvoidArea的具体类型、像素到vp转换、变化订阅及本场景S的对应关系需要准确SDK与实测核实，不能直接把某个topRect.height当作所有窗口的S。查询为空也不能反证此变更未触发。

## 受影响与不受影响示例

已有CENTER面板的builder用旧上限固定为 `windowHeightVp * 0.9`，在新上限较小时可能溢出。若原业务确实需要内容撑满系统面板，且父面板给出明确高度约束，可考虑仅在该builder根节点使用：

```ts
// 已有sheetContent builder内；只有确认需要撑满时使用
Column() { /* 保留原内容和滚动容器 */ }
  .height('100%')
```

不为了此条给所有弹窗加height('100%')。已是按内容高度展示的短面板，且真实场景确认低于新上限、无固定旧公式时无需改成全高。phone/tablet不属于本条2in1限定范围。

## 最小方案与边界

需要撑满的固定高度builder，可在确认父约束和滚动行为后局部改为百分比；确有自算最大高度需求时用新公式并保留最小尺寸/内容滚动策略，但先取得S和单位证据。不要重复给系统已避让的面板叠加同一安全区padding，不为规避变更取消避让或更换弹窗类型。

官方仅提供最大高度和布局建议，没有给出通用查询S的代码。资料中“通过expandSafeArea获取安全区”的说法不能采用。跨系统时新公式不能机械覆盖旧系统，按[target升级兼容](../upgrade-compatibility.md)核对实际发布组合及旧体验目标。

## 验证与证据缺口

在2in1的实际自由窗口/悬浮标题栏场景，记录同一窗口H、S、单位、样式与面板测量值；调整窗口尺寸并切换标题栏，对比CENTER/BOTTOM及短内容/滚动长内容。检查避让、留白、裁剪与关闭操作。真实编译、设备、窗口日志及高度测量均未执行，S的工程取值实现仍需按实际项目验证。
