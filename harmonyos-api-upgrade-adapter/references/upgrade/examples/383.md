# 383-文本与输入、信息展示、按钮与选择、滚动与滑动、图形绘制组件接口支持Resource类型

## 来源与版本

身份：扫描Rule ID 383。变更版本：6.0.0(20) Beta1。

[完整官方章节](../../changelogs/6.0.0(20)/beta1-os-api-behavior-changes.md#文本与输入信息展示按钮与选择滚动与滑动图形绘制组件接口支持resource类型)（起始行318）；[官网原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/changelogs-for-all-apps-6001#section383)。接口起始版本、行为版本与target隔离分别核对，不相互替代。

## 旧新行为

官方清单中的文本与输入、信息展示、按钮与选择、滚动与滑动、图形绘制接口增加Resource类型支持。能力扩展不强制把原string/number实参改为资源对象，也不保证所有继承派生类型无需调整。

## 影响条件与工程核查

按完整接口清单与准确SDK核对真实参数、字段和继承声明；检查是否定义派生样式、是否实际传Resource、业务是否需要新增资源能力。不要因同名color/fontSize或接口标题过长就统一迁移。

## 受影响与不受影响示例

受影响示例：派生样式字段原限制为不含Resource的窄类型，业务现在确需传资源对象，而准确SDK及实际类型检查表明需要相应调整。无需修改：原实参仍满足声明、业务不需新能力，或现有派生定义已覆盖实际取值。仅“有继承”或“接口新增Resource”不能自动判必须。

## 最小方案与边界

只在确需资源能力并核实类型关系后修改相关派生字段/实参，保留已有类型契约；不批量把常量改$r，不为仅重编译的条目制造源码变化。具体类型写法按准确接口和SDK声明，不拿某一个Badge示例套所有接口。

## 验证与证据缺口

真实类型检查及完整构建核对派生声明、原有实参与实际Resource用法；必要时验证资源解析和显示。缺准确派生类型、实参或需求时保留具体缺口；构建未执行明确写未执行。
