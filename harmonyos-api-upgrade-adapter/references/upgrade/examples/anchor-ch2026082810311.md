# ch2026082810311-Image组件autoResize属性默认行为变更

## 来源与版本

身份：官方章节锚点（当前规则包未提供扫描Rule ID） ch2026082810311。变更版本：26.0.0 Release。

[完整官方章节](../../changelogs/26.0.0/release-changes-for-all-apps.md#image组件autoresize属性默认行为变更)（起始行166）；[官网原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/changelogs-for-all-apps-7003#ch2026082810311)。接口起始版本、行为版本与target隔离分别核对，不相互替代。

## 旧新行为

未设置autoResize时，解码后宽×高超过5000万像素的图片由原默认false改为true，开启降采样。判断依据是像素尺寸，不是文件大小、编码格式或接口since；按官方设备行为版本评估，不凭目标26补造target隔离。

## 影响条件与工程核查

读取Image完整属性链及封装，确认是否依赖默认autoResize；沿资源、网络图片和动态替换链取得真实像素尺寸。再确认业务是否需要放大查看原图细节，不能从一张小图代表全部动态资源。

## 受影响与不受影响示例

需要保留原图细节且真实资源超过像素门槛时：

```ts
// 修改前：依赖旧默认值。
Image($r('app.media.large_image'))
```

真实资源固定144×144、无动态大图替换时无需适配；原本已显式配置autoResize的调用按其实际业务判断。资源尺寸未知时保留缺口，不直接判小图。

## 最小方案与边界

业务需要原图细节时显式保留false：

```ts
// 修改后：显式保留按原图尺寸解码的业务要求。
Image($r('app.media.large_image'))
  .autoResize(false)
```

评估原图解码的内存与稳定性成本；原参数已支持false时不额外加版本分支。若业务明确接受降采样控制内存，可显式true，但这不是保留旧默认false，应说明取舍，不能批量补true消除命中。

## 验证与证据缺口

核对高分辨率图的画质、放大细节、内存和稳定性，包含固定小图与动态大图边界。构建通过不证明画质或内存表现；缺少真实资源尺寸或设备结果时分别保留证据缺口与待验证项。
