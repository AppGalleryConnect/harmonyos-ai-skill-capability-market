# CH2025062517095-CanvasRenderer的font接口支持自定义字体行为变更

## 来源与版本

身份：扫描Rule ID `CH2025062517095`。

依据[官方完整章节](../../changelogs/6.0.0(20)/beta2-os-api-behavior-changes.md#canvasrenderer的font接口支持自定义字体行为变更)（315–373行），变更发布于6.0.0(20) Beta2，涉及`CanvasRenderingContext2D`与`OffscreenCanvasRenderingContext2D`的`font`。该章没有target隔离说明，不补造`target ≥ 20`条件；“起始API Level 8”是font原接口版本。

本地API 26 SDK：`openharmony/ets/component/canvas.d.ts:2371–2413`明确font语法及默认`normal normal 14px sans-serif`、自定义字体自API 20支持、预览器不支持自定义字体；两个上下文分别在2787、3098行继承`CanvasRenderer`。`api/@ohos.graphics.text.d.ts:1321,1349`确认`FontCollection.getGlobalInstance()`和`loadFontSync(name: string, path: string | Resource): void`；这里核查的是已有接口声明，不建议为本条升级无关API。

## 旧新行为

旧系统上为Canvas指定已注册的自定义字体仍使用默认字体；新系统上自定义字体生效，字形、宽度、基线和排版可能改变。只有字符串里出现字体名还不等于成功使用：要核对注册别名、资源存在、使用的字体集合及加载完成时机。

SDK指出可通过ArkUI异步`registerFont`注册，也可使用全局FontCollection同步加载；异步调用后立即绘制可能尚未生效。新旧外观判断必须区分系统变更与加载时序问题。修改target并不能证明或规避本条。

## 影响条件与工程核查

检索`.font =`及统一绘图封装，覆盖屏幕和离屏Canvas；追踪font-family是否是自定义别名、字体注册在哪里、资源是否随实际包分发、绘制是否在注册完成后。找`fillText`/`strokeText`、`measureText`、文本宽度驱动的布局、导出图片及缓存路径。

工程证据应同时包含字体注册/加载、同名font赋值、调用时序、实际绘制入口与期望视觉基线。全局FontCollection加载的字体可能被多个页面复用；仅为Canvas去掉一次加载可能破坏其他文字。仅有`font = "50px Brand"`而没有注册证据不能宣称新字体一定生效；缺失字体文件、别名不匹配或只见预览器结果时，记录证据不足。

仅用`sans-serif`/`serif`/`monospace`且无自定义字体依赖，或没有文字绘制的分支，可以排除本条。已经明确接受自定义字体的新排版也可在验证后无需修改。

## 受影响与不受影响示例

`ctx`为已有`CanvasRenderingContext2D`，`Brand.ttf`为包内真实字体；下例在Canvas可绘制且资源存在的回调内执行：

```ArkTS
// text来自@kit.ArkGraphics2D；别名必须与font-family一致。
text.FontCollection.getGlobalInstance().loadFontSync('Brand', $rawfile('Brand.ttf'))
ctx.font = 'italic 500 50px Brand'
ctx.fillText('账单总计', 20, 60)
```

若产品要求保留原默认字体但保持原来的字号、字重和斜体，仅调整本上下文的family：

```ArkTS
ctx.font = 'italic 500 50px sans-serif'
```

不受影响例：原代码已用`ctx.font = 'italic 500 50px sans-serif'`，没有自定义别名；或报表明确要采用Brand且文本与导出回归通过。删除整条font赋值会连带恢复14px等默认值，不能视为等价修复。

## 最小方案与边界

若采用新字体，保留注册与赋值，按真实字形调整确有必要的布局或裁剪。若保留旧默认字体，在受影响Canvas将family换成核实过的系统族，保留字号/样式等其余配置，并核对共享上下文和save/restore边界。只在证实字体加载没有任何其他使用者后才删除多余注册；不要卸载全局字体以解决单个画布的显示问题。

默认字体的实际字形还受设备和语言影响，`sans-serif`不能承诺逐像素复现所有旧设备；以原包与目标设备的真实截图为依据。不把加载失败当成稳定的兼容方案，不只靠DevEco预览器验收。

## 验证与证据缺口

比较同一字符串在中英混排、数字、长文本和缺字场景下的字形、测量宽度、截断/重叠、基线与图片导出；覆盖离屏结果及首次加载、再次进入、字体缓存复用。保存加载时序、别名、资源哈希、系统版本及截图。

本案例的真实编译、资源打包、设备和图像对照均未执行。若字体资源、注册链或旧视觉期望缺失，只能说明风险与补证项，不能断言删除注册即可恢复旧体验。
