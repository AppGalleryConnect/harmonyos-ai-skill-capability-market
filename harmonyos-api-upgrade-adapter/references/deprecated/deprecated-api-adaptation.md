# 废弃API完整迁移流程

本页独立组织deprecated任务，从应用范围与准确SDK声明到完整构建、残留分析和逐行交付。按D01–D11推进，公共专题在需要操作时引用；条件步骤记录执行、跳过或阻断原因。现有入口支持HAP及注册模块/目录范围，不扩展为独立HAR废弃入口。

## 用户决策与确认

D05先汇总全部可评估范围的迁移方案，列符号/重载、文件/rowIds、必要配置、兼容风险、方案选择/推荐、验证及未解决项；展示后请求批准全部、指定部分或暂不修改，再实施代表调用。初始“自动修复/全部处理”不能替代方案展示后的同意，不能先试改再补批。仅分析或全无需修改且无配置调整时不请求无意义的修改批准。

优先使用宿主交互工具，无工具则给清晰选项等待文本答复；推荐、预选、沉默和超时不是批准。部分批准须唯一对应方案和必要共享修改，影响未批准范围先澄清。同一批准方案的实现细节可继续；新增范围、目标或实质迁移/兼容方案变化时，展示差异并重新确认受影响部分。

设备验证只按用户明确要求安排，不主动增加设备询问。单次设备验证只使用本次修改后构建产物，不要求修改前包或采集基线。修改批准与设备授权分开记录；恢复只补缺项、不默认历史已批准，不逐文件重问。

## D01 确定应用与迁移范围

进入子工程前记录宿主任务起始工作目录。按[任务输出契约](../common/task-output.md)初始化一次任务并登记计划应用、保存绝对 taskFile；同任务另一功能已初始化时复用并登记本功能参与应用，不另起时间戳。

- **适用条件**：全部废弃任务与断点继续。
- **输入**：用户目标、应用工程、已有CSV、实际源码及未提交改动。
- **动作**：读取根build-profile.json5和模块module.json5，按实际JSON5解析；确定product、deprecated、应用入口和授权注册模块/目录。同类取并集、不同类型取交集，按物理路径核对junction/符号链接及工程外注册模块，记录已有改动，不猜目录。
- **输出**：唯一工程/product/物理范围、修改/验证目标和已有改动。
- **完成判据**：可准确限定扫描与修改范围；独立HAR输入不自动扩大本入口支持。联合任务协调共享文件/配置，不互代两类结果。
- **异常处理/下一步**：候选有歧义列实际选项询问，无法限定停止该范围并保留事实；明确后D02。

## D02 核对SDK与迁移目标

- **适用条件**：所有任务，实际扫描/构建前核对。
- **输入**：所选product原target/compatible、用户指定目标与工具路径。
- **动作**：按[版本契约](../common/sdk-versions.md#配置设备与打包字段)及[环境核查](../common/verification.md#环境与依赖)先运行内置 inspect-environment，一次读取真实SDK/IDE和配套Node/Java/ohpm/Hvigor。确定目标SDK/target与原compatible；from仅为scanner要求的版本参数，不限制废弃声明出现时间。配置API26写26.0.0，扫描参数保留准确通道，未要求调整的compatible保留。
- **输出**：实际旧/目标配置、准确扫描参数、编译SDK/IDE与工具位置、缺口及必要用户答复。
- **完成判据**：按目标全量废弃检测，SDK可高于target，compatible≤target≤编译SDK，不擅自升级/降低配置或混淆Beta/Release。无法由任务和工程唯一确定目标时询问，不靠工具安装版本代选。
- **异常处理/下一步**：路径无效不偷偷换SDK；缺工具可继续已有CSV的可信静态分析，不能虚构扫描/构建成功。目标/SDK覆盖不足暂停相关工具步骤，可信部分仍交付D11；可执行时D03。

scanner当前两种模式均要求from<to。废弃任务没有显式from时，使用scanner认可且早于目标的最早技术基线；当前内置基线为`5.0.0(12) Release`，执行前按实际版本解析确认。目标已为26时也可使用12→26，不制造26→26区间、不回退工程配置。这个技术起点不代表工程原target/compatible，不限制目标SDK中的废弃声明时间。用户显式from须保留并验证；无效或不早于目标时报告并澄清，不静默换值。没有合法早于目标的基线则停止扫描，保留可信静态部分。

## D03 扫描或导入废弃记录

- **适用条件**：新扫描、已有/历史CSV及零命中。
- **输入**：D01/D02及原始CSV、扫描JSON、coverage/diagnostics。
- **动作**：先执行scanner真实help，再用下方deprecated命令。使用 D01 绝对 taskFile 中固定的启动根和输出位置；按[目录与原件](../../templates/progress.md#建议目录)使用工具返回的实际路径。导入通过 import-csv --task 复制原字节及伴随证据到同一任务，不以较小adapted表为原基线、不搬动原表、不恢复旧账本/批次状态。
- **输出**：原件/副本路径与SHA-256，deprecated交付目录、真实退出码、覆盖/诊断与来源边界。
- **完成判据**：区分全量覆盖、未解析/依赖、后端失败和CSV_ONLY。保留全部原始列和逻辑行。新 CSV 的 Replacement API 仅作替代提示；API Symbol ID、列号、废弃时间、Replacement Source 和 Detection Source 从同批次扫描 JSON 读取，不要求它们出现在精简 CSV 中。
- **异常处理/下一步**：失败保留已扫描可信部分及未覆盖范围，不用grep代替后端；原件变化先核查。可处理行进D04，完全受阻仍D11；排错方法见[公共专题](../common/troubleshooting.md)。

```console
node "<skill-root>/scripts/scanner/bin/harmony-api-scan.mjs" help
node "<skill-root>/scripts/scanner/bin/harmony-api-scan.mjs" scan --task "<绝对taskFile>" --mode deprecated --project "<工程>" --sdk "<SDK>" --deveco-home "<IDE>" --from "<真实版本参数>" --to "<目标SDK精确版本>" --product "<产品>"
```

## D04 解析并按准确符号归组

- **适用条件**：全部原始行，包含重复、范围外和零行。
- **输入**：原始CSV、伴随扫描JSON、准确声明身份与实际物理范围。
- **动作**：直接调用[内置 CSV inspect](../../templates/results.md#格式化接口与文件调用)可靠解析CSV，用输入SHA-256+逻辑数据行序号构造rowId，保留原列/原序/全部重复行；范围外/其他功能标原因不删除。按SDK符号、接收者、声明/重载及物理文件归组，身份不明独立保留；类与成员双命中分别编号。新批次按 JSON actionGroups 的顺序核对 CSV 行及可见字段，读取 occurrences 中的完整身份；同一行多调用和显示相同的记录仍逐条保留。只有 CSV 时按完整签名、代码位置、接收者和真实 SDK 声明补证，不能唯一确认的保留 EVIDENCE_GAP，不凭方法名合并。调用csv prepare --task --project --mode deprecated初始化[分组rowResults与通用进度](../../templates/progress.md#分组示例)，模型直接编辑逐行判断，不填行为分类；评估及修改结论更新后csv validate，再任务模式write。本页[迁移记录](#废弃迁移记录)保存完整取材。
- **输出**：原始行→SDK符号→物理文件/工作单元与局部证据缺口。
- **完成判据**：不按模糊名称或方法名子串合并；原始行、位置、物理文件、符号和工作单元分别统计，不套用行为三类分类。
- **异常处理/下一步**：解析/身份/文件缺失保留具体问题，不吞重复、不删未完成组；零行D11，其余D05。

## D05 逐文件制定并批准迁移方案

- **适用条件**：每个废弃候选及关联调用文件。
- **输入**：SDK旧/替代声明、接收者与重载、全部实际调用/消费者、业务与已有依赖。
- **动作**：按[声明与替代](#声明与替代)和[迁移选择顺序](#迁移选择顺序)核对准确useinstead、各新增调用/参数since、来源/可空/生命周期、返回/回调/异常契约。修改前读[兼容](../common/compatibility.md)和适用[编码规范](../common/arkts-coding-standards.md)；Context命中读[Context迁移](context-migration.md)。先分析代表调用与其他文件前提，写逐文件方案/验证并汇总，取得本页要求的批准后才试改。
- **输出**：准确替代依据、逐文件计划、必要配置/兼容/验证、实际批准范围或待决定/缺口。优先推荐完整构建和复扫，不运行设备测试；单次设备验证仅按用户明确要求安排，不要求前后对比。
- **完成判据**：覆盖关联声明和消费者，不因非组件没有this或旧API低版本可用而跳过。准确SDK可提供替代事实，不要求必须有changelog；已评估与已解决分开。
- **异常处理/下一步**：局部声明/业务证据不足分别记录EVIDENCE_GAP/DECISION_REQUIRED，独立单元可继续。未获展示后方案批准不修改；无修改计划不要求批准。获批后直接D06，暂不修改则D11交付可信分析。

## D06 实施获批迁移与跨文件修改

- **适用条件**：已有方案展示后的实际批准；无需修改、未批准和缺口行也保留结果。
- **输入**：逐文件方案、批准范围、当前源码和已有用户改动。
- **动作**：先在获批范围修改代表调用，再按相同前提推广到全部关联文件；声明/内部调用链/必要导入同步最小修改，不破坏公开接口或新增依赖。按[异常与异步](#异常和异步契约)保留参数求值、返回/resolve/reject/回调及生命周期，核对替代链since和真实低版本回退；定点修改所选product获批必要配置，保留签名/其他产品。每文件更新差异/结果，编译置待执行。
- **输出**：真实源码/必要配置差异、逐行结果和迁移进度。
- **完成判据**：每个MODIFIED有相关实质差异与兼容依据；一个修改覆盖类/成员多行须分别解释。日志/格式/根配置或同文件其他修改不算该行修复，未批准不记NO_CHANGE/MODIFIED，原Fixed保留。
- **异常处理/下一步**：实质方案/范围/目标变化回D05/D02确认受影响部分；未知归属与缺上下文保留，不覆盖任务外改动/整文件回滚。完成D07。

## D07 复核迁移语义与配置

- **适用条件**：修改后及相关输入再次变化。
- **输入**：实际diff、准确SDK、所有调用者、旧新配置及工程约定。
- **动作**：按[通用静态复核](../common/verification.md#通用静态复核)及[废弃迁移兼容复核](../common/verification.md#废弃迁移兼容复核)检查准确接收者、参数/返回、辅助链since、低版本回退、成对on/off、可空性、异常/Promise/失败出口；回读配置并执行实际可用SDK/IDE检查，区分新增与历史诊断。
- **输出**：模型复核与工具通过/失败/未执行分别记录，配置实际值及待修闭包。
- **完成判据**：原业务和失败出口保留；不使用不安全转换、空catch或虚构默认值掩盖迁移问题。模型复核或仅新增错误为0不代替全量检查通过。
- **异常处理/下一步**：源码失败仅修必要范围后回D06/D07，最多三种实质源码失败方案；工具缺失明确保留。可构建D08，受阻D11部分交付。

## D08 完整构建并确认当前产物

- **适用条件**：每轮源码/构建配置修改后必须执行；未修改按任务验证范围安排。
- **输入**：本轮最终源码/配置、真实配套SDK/Java/ohpm/Hvigor、product和模块。
- **动作**：按[完整构建](../common/verification.md#完整构建与产物)通过内置构建取证入口每次先在工程根执行 ohpm install，即使 oh_modules 存在也执行；安装失败不启动 Hvigor，成功后完整构建HAP，保留实际参数/cwd/版本/日志/退出码，核对本次新产物身份、大小/哈希及副本，不能只看日志前部成功任务。
- **输出**：当前输入对应的编译、产物与签名/安装事实。
- **完成判据**：真实构建成功且有对应本次产物；模型检查、废弃复扫、旧包或命令未启动均不代替成功。后续源码/配置/SDK变化后相关成功失效需重建，高版本编译不证明低版本设备通过。
- **异常处理/下一步**：代码失败回D06/D07，环境/依赖/签名/超时不消耗源码方案次数，条件未变不空重试。未构建成功到D11部分完成/待编译交付，保留现场。成功D09。

## D09 真实复扫与残留分类

- **适用条件**：废弃修改后必须；未修改时按验证安排说明实际执行或未执行。
- **输入**：原始扫描、当前源码、相同deprecated模式/product/目标/范围及SDK。
- **动作**：用D03真实scanner生成新批次，保留原件和真实覆盖/诊断；按准确符号、迁移归属和当前调用位置对应rowIds，分别解释未迁移、合法受保护低版本回退、依赖问题、工具缺口与新引入问题。行号移动不机械按旧数字匹配。
- **输出**：复扫路径、覆盖/诊断、各类残留及关联原始行。
- **完成判据**：原候选均有解释，新废弃/未保护残留已修或列待办；合法回退不为清零删除，依赖源码不改。数量下降或归零不证明迁移语义正确，不缩小范围制造完成。
- **异常处理/下一步**：复扫失败/不完整明确缺口，不关闭残留验收；实际问题回D05/D06-D09并重新验证，独立可信部分保留。然后D10或D11交付。

## D10 按要求验证实际迁移功能

修改后复扫必须复用 taskFile、product 和原范围，并显式增加 --scan-purpose rescan。复扫原表只在内部扫描目录，不生成 adaptedCsv、不覆盖 D03 的原始基线，也不创建新的外层时间戳。

- **适用条件**：用户明确要求设备/业务验证；未要求则记录NOT_RUN并跳过，不额外询问。
- **输入**：当前构建HAP、明确设备/系统、迁移rowIds与用例/前置数据。
- **动作**：按[单次设备验证](../common/verification.md#单次设备验证)和[通用功能取证](../common/runtime-functional-tests.md#通用功能取证)安装本次构建产物，执行用户要求的功能用例，保存实际调用、返回/回调/异常、设备/系统、日志与图片。验证范围按实际请求记录；先保存现场，再只清理本次启动实例并确认状态。
- **输出**：本次运行、功能、视觉、实际覆盖与清理的独立结论和原始证据。
- **完成判据**：每个通过结论有本次真实操作与相关观测，不以仅启动、截图或零用例代替功能；代码或产物变化后相关结果须重新验证。
- **异常处理/下一步**：设备歧义不换实例，已有实例保留，启动/停止失败与模型中断分别记录，不冒充业务失败/通过。全部结局D11，缺设备或低版本列具体未验收。

## D11 核对迁移覆盖并交付

- **适用条件**：正常、零命中、全无需修改、待批准、证据不足、失败或停止。
- **输入**：全部原始行、准确替代依据、批准、实际差异、进度及检查/构建/复扫/设备证据。
- **动作**：按[逐行结果](../../templates/results.md)调用内置CSV write --task --project --mode deprecated从分组rowResults生成结果表，不现场编写格式化脚本，回读每行唯一对应和全部重复；主 agent 按[固定报告命令与输入](../../templates/html-reports.md#固定报告命令与输入)直接调用report render --task --mode deprecated，不传--data；分组changeSummary保存一次旧新行为及方案说明，进度保存工程信息，不另写报告JSON，工具保留[废弃 HTML 模板](../../templates/deprecated-report.html)完整样式并从同一逐行投影生成CSV与HTML明细，不现场编写生成脚本。按任务索引列全计划应用并逐工程展开，未开始和失败项同样纳入；先展示product/范围与配置实际旧→目标及实施状态，再按六类处理结论逐行概括。核心结果默认展示，逐符号/文件的替代依据、迁移、兼容、残留、批准/未实施、失败与下一步保留在折叠详情，核对原件哈希和文件实际可读。
- **输出**：原扫描、adapted-results-<批次ID>.csv、api-adapt-report.html、轻量进度及证据的完整路径。
- **完成判据**：六类合计等于原始逻辑行数，重复单列计数；记录/位置/物理文件/符号与工作单元不混。评估、修改、编译、复扫、运行和最低版本分开；遗漏/过期/未成功编译只能部分完成，扫描工具缺口单独说明。
- **异常处理/下一步**：交付被用户修改另存版本，不覆盖；清除模板提示、回读 HTML 和全部文件链接，将实际报告路径写入进度与最终答复。任何失败仍保留可信成果。按[继续与撤销](../common/troubleshooting.md)核对当前输入、实际批准与旧证据，回到受影响D步骤；不重置停止次数、不继承旧Fixed成功或恢复旧账本。

## 声明与替代

按目标SDK全量检测废弃调用；扫描from不是废弃声明时间下限。ArkTS 依据 SDK 声明检测，C/C++ 依据 DevEco 废弃规则检测，命中均进入原始 CSV。保留原始行；从扫描 JSON 或历史 CSV 读取 API Symbol ID、Replacement API/Source、Detection Source，标明来源及缺口，不要求新 CSV 包含已移出的字段。相同调用同时命中废弃类和成员时，两行分别保留并解释同一次修改如何覆盖。

从真实SDK读取旧声明、准确接收者、重载、useinstead及替代声明；不能把业务同名方法当SDK、匹配方法名子串或按所有重载取最大since。替代例子没有写在changelog不等于无法迁移，优先核对SDK提供的替代事实；声明真正冲突才留局部缺口。

since必须来自调用绑定的准确接口/成员/参数声明。错误码、crossplatform、atomicservice等标签不是接口起始版本。保留HMS平台版本、整数API和原文，无法解析说明具体标签/声明问题，不直接写“SDK没有since”。

## 迁移选择顺序

先分析代表调用并核对其他文件是否满足相同前提，将逐文件迁移、必要配置、兼容风险与验证安排汇总，按[用户决策与确认](#用户决策与确认)取得批准后才修改和验证代表调用，再沿批准范围批量落地；每个原始文件和行仍有独立结果。不能先试改代表调用再请求批准，也不能只因“旧API低版本可用”或“不是组件没有this.getUIContext”跳过分析。

上下文命中必须读取[Context迁移](context-migration.md)：组件自身UIContext → 已有参数/成员/真实Window → 完整内部调用链传入最小Context → 仅在已有依赖与生命周期可证明时复用受控服务。保护公开HAR/HSP接口，不为了统一方案新增模块依赖，不在各文件复制AppStorage WindowStage链。

实例/构造器替代保留原locale/options、缓存身份、参数默认值、回调和生命周期；构造器注入采用显式字段/赋值，遵循ArkTS限制。读取[废弃迁移样例](deprecated-api-examples.md)中实际命中的章节，不能把示例前提套到所有文件。

## 兼容与残留

替代调用/辅助链的since及低版本完整方案按[公共迁移兼容要求](../common/compatibility.md#迁移调用的版本与回退)核对；准确接收者和方法差异读按Kit样例。

合法低版本回退中仍有旧调用可以解释为受保护残留，不能只为复扫清零删除回退。替代方案不得引入其他废弃API。依赖告警保留来源/升级建议，不修改oh_modules或把外部依赖当本工程修复成果。

## 异常和异步契约

迁移前后准确throws、获取失败和所有消费者按[公共编码规范](../common/arkts-coding-standards.md#异常异步与-api-迁移)及其表达式/失败出口要求复核；通用规则与示例不在本流程重复维护。真实SDK替代、组件/窗口来源和迁移代码分别读[Context专题](context-migration.md)与[按Kit样例](deprecated-api-examples.md)。

## 验证与结果

修改及必要配置只在D05汇总方案已获批准的范围实施，遵守共用兼容与适用编码规范；部分批准、暂不修改或待答复分别记录，未批准不实施，不当作无需修改。实质方案变化回D05确认，仍适用的批准不逐文件重问。随后D07真实可用检查、D08完整构建、D09真实复扫；按用户要求D10设备验证，任何结局都D11按[废弃报告模板](../../templates/deprecated-report.html)交付，突出方案答复、SDK替代声明、逐文件迁移与残留分类。修改后未真实编译成功时只能标部分完成/待编译或失败，不能用复扫清零替代。

每个结果写MODEL_ASSESSED，MODIFIED说明相关真实差异与兼容理由；NO_CHANGE、DECISION_REQUIRED、EVIDENCE_GAP和未处理分别报告。语义判断、编译和最低设备验收独立，不用文件变化、构建通过、残留清零或旧Fixed推定自动证明。

## 废弃迁移记录

使用同一份[通用进度](../../templates/progress.md)和[逐行结果](../../templates/results.md)。decisions.repair记录汇总方案、实际答复及approvedItems；decisions.target保存目标来源，runtime按实际请求记录未要求、不运行或单次设备验证，不强制等待未要求的设备选择。

组identity使用准确SDK符号、接收者/重载与声明位置，files.evidence关联旧/替代声明、各辅助链since和实际源码；plan写最小迁移及兼容/验证安排。跨文件声明、调用者及共享修改一并关联，类/成员双命中保留各rowId与覆盖解释。

在现有reason/evidence/next保留复扫对应、未迁移/合法回退/依赖/工具缺口/新问题及下一步；不增CSV列，不填写行为knowledge、rowClassifications或三类分类。报告首页按NO_CHANGE、MODIFIED、DECISION_REQUIRED、EVIDENCE_GAP、PENDING、OUT_OF_SCOPE逐逻辑行核对。
