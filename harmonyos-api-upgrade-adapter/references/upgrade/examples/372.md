# 372-XComponent设置为Texture模式使用blendMode接口的行为由不生效变更为正常生效

## 来源与版本

身份：扫描Rule ID `372`。

[完整官方章节](../../changelogs/5.1.0(18)/os-api-behavior-changes.md#xcomponent设置为texture模式使用blendmode接口的行为由不生效变更为正常生效)位于5.1.0(18) Release，明确targetSdkVersion≥5.1.0(18)生效，本地标题映射确认扫描RuleID为372。官方起始API Level11指blendMode；不把Texture枚举起始版本与行为门槛混用。

本机SDK26.0.0.105 Release的 `ets/component/enums.d.ts` 声明XComponentType.TEXTURE（since10）；`common.d.ts` 声明BlendMode.NONE、XOR、SRC_OVER与blendMode。官方适配文字写BlendMode.None，而同章表格使用NONE；本机准确声明只有 `NONE`，本案例代码用 `BlendMode.NONE`，实施前仍核对真实工程SDK。

## 旧新行为

XComponent为Texture模式时，原本blendMode不生效，变更后按参数正常生效。非NONE模式可能改变重叠区域显示；并非所有XComponent都改变，也不能为保留旧效果改成Surface模式。NONE表示不进行指定混合，SDK说明其显示合成默认SRC_OVER，且BlendApplyType不生效；不将NONE等同于XOR或一般SRC_OVER调用的所有离屏语义。

## 影响条件与工程核查

沿XComponent构造选项追踪实际type，读取完整属性链、modifier、动态blendMode和祖先离屏层，核实native绘制内容、重叠关系与真实混合需求。必须在同一组件确认Texture和blend调用，不能凭附近关键词拼接。

非Texture、没有blendMode、实际NONE且无动态非NONE分支，可排除此条混合差异。Texture+非NONE虽命中，也要确认是否业务现在需要该混合；需要保留旧无混合效果才提出NONE方案。native库/绘制内容缺失影响视觉判断，应具体记录而非伪造截图结论。

## 受影响与不受影响示例

下面保留原id、type和native库，只展示已核实Texture、原XOR实际不生效且业务要求保持旧视觉时的属性修改位置：

```ts
XComponent({
  id: 'rect',
  type: XComponentType.TEXTURE,
  libraryname: 'nativerender'
})
  .blendMode(BlendMode.NONE)
```

它替换该节点原来的 `.blendMode(BlendMode.XOR)`；不删除祖先合成层或重写native绘制。SURFACE节点没有本条Texture条件；Texture节点已经NONE且没有动态覆盖，也不需要重复修改。

## 最小方案与边界

需要保持旧未生效视觉时，仅针对命中Texture节点把blendMode改为真实SDK的NONE；业务需要新增的正确混合时可保留原参数并记录决定。动态模式先核实各分支，不批量替换所有blendMode，不因文档大小写笔误写不存在的枚举。

若同节点还涉及离屏opacity，需分别评估373及共享祖先影响，不能认为改NONE自动证明透明度与全部背景效果一致。跨系统按[target升级兼容](../upgrade-compatibility.md)核对原/最终包实际组合，接口类型可用不能证明native合成视觉。

## 验证与证据缺口

使用真实native库与绘制触发，比较原/最终包的重叠区域、边缘、透明背景和动态模式；检查NONE对照与未改的其他节点。编译只证明接口和库链接，不能代替native绘制或截图。真实编译、native加载、设备合成及截图均未执行。
