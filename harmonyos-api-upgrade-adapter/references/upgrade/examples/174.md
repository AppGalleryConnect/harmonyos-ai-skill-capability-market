# 174-按钮默认值变更为新增圆角矩形类型

## 来源与版本

身份：扫描Rule ID 174。变更版本：5.1.0(18) Release。

[完整官方章节](../../changelogs/5.1.0(18)/ux-style-and-effect-changes.md#按钮默认值变更为新增圆角矩形类型)（起始行10）；[官网原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/changelogs-ux-5101#section174)。接口起始版本、行为版本与target隔离分别核对，不相互替代。

## 旧新行为

官方明确target≥5.1.0(18)时，ButtonOptions.type默认值由Capsule变为ROUNDED_RECTANGLE。本例关注适老化放大场景的形状差异，不能把默认枚举改变推成所有未写type的按钮视觉都会改变；未开启跟随系统字体时，不因本条补Capsule。

## 影响条件与工程核查

先读取当前应用AppScope/app.json5。按[官方适老化指导](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/arkui-support-for-aging-adaptation)，应用默认不跟随系统字体大小变化；未配置configuration引用时，按此默认行为判断，不因缺少可选配置列EVIDENCE_GAP，也不默认要求排查窗口、UIContext或初始化链。

存在app.configuration引用时，再沿真实资源引用读取生效profile；不能只凭搜到或没搜到configuration.json判断。以下仅展示开启字体跟随的相关字段：

```json
{
  "app": {
    "bundleName": "com.example.myapplication",
    "configuration": "$profile:configuration"
  }
}
```

对应resources/base/profile/configuration.json：

```json
{
  "configuration": {
    "fontSizeScale": "followSystem",
    "fontSizeMaxScale": "1.3"
  }
}
```

fontSizeScale表达是否跟随系统字体，fontSizeMaxScale是上限，1.3不是适老化统一阈值，也不保证产生圆角差异。引用存在时核对实际profile及当前product/资源限定；引用文件缺失或无法解析才列具体配置证据缺口。

## 受影响与不受影响示例

| 已核实事实 | 判断 |
| --- | --- |
| 已读取app.json5，未配置configuration引用 | 按官方默认行为不跟随系统字体，本条无需适配，不补Capsule，不列配置缺口 |
| 生效配置明确不跟随系统字体 | 无需适配，不批量补Capsule，也不要求用户接受新圆角 |
| 跟随系统字体、依赖默认type，实际放大场景有差异且业务要求胶囊 | 提出局部显式Capsule方案 |
| 完整属性链、共享样式或modifier有效锁定原类型/圆角 | 核对覆盖及状态后可无需修改 |
| configuration引用存在，但对应profile缺失或无法解析 | EVIDENCE_GAP，说明实际引用和缺失文件，不猜配置值 |

只有实际发现与字体缩放有关的动态设置时，才按该代码分析具体影响；不把假设性的覆盖作为默认核查要求。

应用自有字号滑块、Text.fontSize乘比例，只证明应用内字号功能，不等于Button跟随系统字体。

## 最小方案与边界

仅受影响且需保留旧形状时，参考：

```ts
Button('操作')
  .type(ButtonType.Capsule)
```

不为圆角问题关闭整个应用的字体跟随能力；开启followSystem也不表示每个按钮都需修改。保留共享样式和状态覆盖，不仅看构造首行。

## 验证与证据缺口

覆盖普通字号及应用实际允许的系统大字号/关怀模式，核对形状、多行文字和裁切。没有设备结果时明确待验证边界，不以构建通过证明放大场景；不为验证本条擅自开启原本关闭的适老化配置。
