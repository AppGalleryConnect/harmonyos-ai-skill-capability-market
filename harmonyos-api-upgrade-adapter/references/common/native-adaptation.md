# C/C++行为适配专题

本页提供行为任务的真实扫描上下文、SDK声明理解、必要修改及ABI构建方法。设备行为差异按[target升级兼容](../upgrade/upgrade-compatibility.md#arkts-与-c-行为分支)处理；不增加通用接口可用性匹配、弱引用迁移或自动最低系统验收，保留已有有效逻辑。

## 扫描与输入边界

保留scanner逐模块DevEco后端、真实compileNative/Ninja上下文、nativePasses、超时和完整性诊断。一模块超时不丢弃其他模块或ArkTS结果；零行或数量相同不能证明完整，不能用grep或伪造AST兜底。

长扫支持范围和 `--cpp-module-timeout-seconds` 的取值见[扫描器参数](../../scripts/scanner/README.md)。整模块超时、后端返回跳过文件、JAR 执行失败或回报已扫描 0 个文件分别记录。只将完成的语义结果纳入 CSV，行为 HTML 的遗留事项保留覆盖缺口摘要及证据链接。

对已核验的 IDE 引擎，仅对其返回且属于本次模块和源码范围的失败文件生成独立文本候选。行为 HTML 将候选折叠展示在工程正文「DevEco 规则包覆盖条目」末尾。即使无候选，仍按语义扫描回执保留覆盖缺口。

scanner按已核实的后端选择规则使用实际Ninja，其他变体仅记录为未使用，不删除或为其过期批量重建。build.ninja早于普通源码不单独表示上下文过期；以实际CMake生成依赖、配置及当前工程来源核对。需要重建时先安装依赖并使用已确认的buildMode，本轮每模块最多一次；选择策略、来源或buildMode无法确认时保留具体缺口。扫描前后核对选中路径和输入哈希，只说明实际记录的ABI覆盖，不代替其他ABI检查。

ArkTS/TS和C/C++使用各自源码及声明；HAR/HAP/HSP/ABC、.so/.a/.o等二进制只核对构建/依赖字节，不输入文本或AST。额外头文件/源码路径限注册和授权范围。

## 逐调用判断

读取准确SDK C声明和实际上下文，理解参数、返回值、错误码、内存/线程/生命周期、官方行为触发条件；按真实ABI、宏及编译条件复核，不用一个ABI结果代表全部。

函数指针、间接调用、复杂宏或声明冲突无法可靠确定时保留具体证据缺口或业务决定，不按同名函数强改。实际差异不等于语义正确，必要的新旧行为分支按官方边界处理，不引入独立的接口版本匹配或弱引用迁移。

## 修改与真实构建

只改必要调用、头文件及真实构建配置，保持ABI和原业务；不删ABI、缩范围或改宏隐藏错误。只需更新NDK重编译时可NO_CHANGE，保存真实工具链及ABI构建日志。

使用工程真实Hvigor/Ninja/clang检查，保存编译参数、链接依赖、命令、退出码、日志与当前产物；真实错误按[排错方法](troubleshooting.md)修必要范围。若用户选择设备验证，检查当前实际包中的业务调用、返回/回调和相关ABI，按[通用功能取证](runtime-functional-tests.md#通用功能取证)保存证据，只在已有授权覆盖行为边界时记录两侧结果，不自动扩展最低系统或接口可用性验收。
