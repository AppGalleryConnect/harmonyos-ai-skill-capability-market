# 从CSV调用点理解业务路径

本能力只读工程，产出访问事实，不生成业务断言或执行设备操作。行为U05确定测试选择后、U06修改前读取本页；保留原始上下文，U08只补充有来源的阶段定位差异。

## 输入与范围

读取本批次原扫描CSV、实际选择展开后的sources.json、评估分组、获批spec、SDK和真实模块/宿主注册。每个引用使用sourceId与完整rowId，不用行号简写代替身份。全部选择必须包括无需适配项；未知分类、缺文件、缺宿主不能消失。

## 白盒分析

对每个选中调用点阅读完整函数或组件及必要直接调用者，记录：实际参数和接收者、入口页面、组件树与定位依据、触发事件、条件分支、回调/返回/持久化出口。读取必要的路由注册、公共封装和HAR宿主消费；不建立与本次调用点无关的全工程调用图。

同一文件不等于同一触发路径。例如showToast位于完整对话框确定回调、取消回调、防连点和普通清空时，分别保留触发条件。某个分支没有额外扫描行，也不能在它是所选调用的必要验证条件时被省略。

## 输出

按[契约](runtime-contracts.md)生成route-map.json。每条路径保留原始行引用、真实源码相对路径、读取起止行和实际片段，从launch开始逐步到达业务操作入口；多个入口分开记录。动态路径未核实、组件没有被宿主消费时使用blockedReason和空steps，并在规格中保留对应缺口。

同一条访问路径可以服务多个测试点，但必须说明这些行实际如何到达。路径只解决到哪里、如何到达；进入页面后的分支触发和业务断言交给[用例设计](runtime-case-generation.md)。保存真实读取的源码内容；不得用修改后的实现或README页面清单替代原始调用链。
