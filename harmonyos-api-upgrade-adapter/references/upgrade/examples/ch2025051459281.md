# CH2025051459281-动画接口在播放次数为无限循环时的行为变更

## 来源与版本

身份：扫描Rule ID CH2025051459281。变更版本：5.0.1(13) Release。

[完整官方章节](../../changelogs/5.0.1(13)/release-os-api-behavior-changes.md#动画接口在播放次数为无限循环时的行为变更)（起始行42）；[官网原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/changelogs-for-all-apps-b112#动画接口在播放次数为无限循环时的行为变更)。接口起始版本、行为版本与target隔离分别核对，不相互替代。

## 旧新行为

本条修正首次布局同步回调中的状态修改被意外纳入无限循环动画的问题，不等于全部动画或所有onFinish改变；官方未声明target隔离，不凭接口since或目标版本补造隔离。

## 影响条件与工程核查

确认真实动画入口/接收者及iterations=-1，再沿首次布局的onSizeChange/onAreaChange等同步回调确认状态修改是否被带入，核对业务原本希望循环哪些属性。

## 受影响与不受影响示例

受影响：业务依赖同步布局回调副作用进入无限循环，或这些副作用产生多余动画。有限循环、没有相关同步回调依赖的调用按实际条件可无需修改。不要与153号退后台有限动画onFinish变化混用。

## 最小方案与边界

真正需要循环的状态显式放进动画闭包，不需要循环的布局/业务状态放在外部。以下使用组件已有字段：

```ts
// 组件已有状态示意：布局变化不参与循环，旋转参与循环。
this.contentWidth = 200;
this.getUIContext().animateTo({ iterations: -1, playMode: PlayMode.Alternate }, () => {
  this.rotateAngle = 90;
});
```

不统一修改iterations，不为保留偶然效果把全部回调状态搬入无限循环；保留停止与资源清理路径。

## 验证与证据缺口

核对预期参与动画的属性、非动画布局、重复触发和终止行为。单帧截图或日志不证明无限循环及清理语义；回调链或状态用途不明时列缺口。
