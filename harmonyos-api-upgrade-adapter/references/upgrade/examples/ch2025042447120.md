# CH2025042447120-ArkUI双指长按行为变更

## 来源与版本

身份：扫描Rule ID `CH2025042447120`。

依据[官方完整章节](../../changelogs/5.1.0(18)/os-api-behavior-changes.md#arkui双指长按行为变更)（796–817行）。5.1.0(18) Release在手机、平板优先响应系统双指操作，默认禁用应用内双指长按。原文没有target版本隔离，不能以target低于18排除；起始API Level 7是LongPressGesture本身的版本。

本地API 26 SDK的`openharmony/ets/component/gesture.d.ts:1386–1429`确认API 18起部分设备系统双指长按优先，`fingers`是触发长按的最少手指数（1–10，默认1），`duration`默认500ms，`repeat`默认false；1464、1476、1488行提供onAction、onActionEnd、onActionCancel签名。

## 旧新行为

旧行为可用`LongPressGesture`指定最少手指数并接收应用长按事件；新行为下恰好两根手指长按组件不会触发应用长按，一根及其他多根手指的长按不受本次变更影响。这里描述的是系统事件优先；不推断所有设备必然唤起同一种系统菜单。

`fingers: 2`是明显线索，却不是完整判断范围。默认`fingers: 1`或显式1的长按若产品确实依赖用户用两根手指操作，也要核查；最少手指数为2的代码仍可在三指下触发，不代表双指业务仍可用。

## 影响条件与工程核查

核对支持的设备类型、实际系统版本、长按入口、手势组/高优先级手势和封装参数，再核对用户操作说明、测试用例及回调中的业务。追踪onAction、持续触发、结束和取消回调是否共同维护选中/预览状态，不能只迁移首次触发。

检索`LongPressGesture`及动态options，确认实际fingers值和用户实际手指数；同时查页面文案如“双指长按预览”。工程证据应包含入口代码、回调实现、交互说明、设备信息和触摸记录。不能仅凭正则未匹配`fingers: 2`断定不受影响。

纯单指操作且已验证不会把双指作为业务入口，或三指专属业务，在本条可无需修改；不涉及LongPressGesture的手势也不按本条批量替换。只有封装调用而options、业务回调或设备类型不明时，保留证据不足。

## 受影响与不受影响示例

以下为页面组件的手势片段，`this.showPreview()`是工程已有预览业务方法；产品明确写着“双指长按预览”：

```ArkTS
.gesture(LongPressGesture({ fingers: 2, duration: 600 })
  .onAction(() => { this.showPreview() }))
```

若产品已决定改为单指长按，并排查与拖拽冲突，可局部调整：

```ArkTS
.gesture(LongPressGesture({ fingers: 1, duration: 600 })
  .onAction(() => { this.showPreview() }))
```

该片段仅说明新入口，真实业务原有repeat、结束/取消处理必须保留。无需修改例：明确仅支持单指的收藏菜单，回调及用户说明都不依赖双指，真机单指测试通过。反例：`LongPressGesture()`的产品说明仍要求双指，不能因默认1而排除。

## 最小方案与边界

优先按业务可达性选择替代入口，如可见按钮或已确认的单指长按；改动必须同步引导文字和原取消/结束语义，检查误触、拖拽、滚动及无障碍。修改为三指虽在本条未受影响，但改变用户动作，不是无需沟通的等价修复。不能用调低duration、增加优先级或换成parallelGesture来承诺抢回系统双指事件。

若业务必须保留双指，官方给出IssueReporter申请白名单例外路径。申请结果和设备生效均是外部依赖；没有批准与实测不能标已适配，也不能编造应用内开关。对已有白名单需要核实应用身份、版本/设备范围及真实回调，不能只依据口头声明。

## 验证与证据缺口

在支持的手机和平板分别测试单指、恰好双指、三指、未达时长、中途松开、重复长按，以及与拖拽/滚动的交互；确认替代入口能完整进入并退出原业务，系统双指操作不被无意干扰。白名单方案分别保留已获批环境与对照环境证据。

本案例真实编译、触摸注入、设备和白名单验证均未执行。没有实际手势配置、交互需求或设备信息时输出证据不足；静态检索命中只能定位核查范围。
