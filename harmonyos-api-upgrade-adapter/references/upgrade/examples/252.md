# 252-Image组件的borderRadius接口支持动态修改

## 来源与版本

身份：扫描Rule ID `252`。

完整名称及ID已与名称映射核对。依据[官方完整章节](../../changelogs/5.0.2(14)/os-api-behavior-changes.md#image组件的borderradius接口支持动态修改)（483–545行）。变更发布于5.0.2(14) Beta1，明确以应用`targetSdkVersion ≥ 5.0.2(14)`隔离；章节的“起始API Level 7”是接口起始版本，不是本次生效门槛。

本地SDK核查：`openharmony/ets/component/image.d.ts:743`的`ImageAttribute`继承`CommonMethod<ImageAttribute>`；`common.d.ts:18250`声明`borderRadius(value: Length | BorderRadiuses | LocalizedBorderRadiuses): T`。SDK为API 26（26.0.0.105），声明核查不能代替API 14设备验证。

## 旧新行为

旧行为下，Image已经显示后动态修改`borderRadius`不生效；新行为下生效。差异是更新传播后的圆角效果，不是首次赋值被统一改写。目标SDK低于14时，本条已隔离的行为保持旧规格。

状态参数并不等于缺陷：若产品本来希望选中头像变圆，升级后正常响应可以直接接受；若同一状态同时服务其他UI，而图片被要求保持初始圆角，则应隔离图片的圆角输入。高频指导中的“去掉装饰器”不能作为通用修复，会阻断其他依赖该状态的UI刷新。

## 影响条件与工程核查

按实际product核对打包target，定位`Image(...).borderRadius(...)`及通过属性修饰器设置圆角的调用，再追踪参数来源：字面量、常量、状态、对象角值、父组件传参或资源。继续找实际写入点、异步回调和用户交互，确认图片仍存活时会否改变该输入。

要保留的工程证据包括：调用及参数声明、从事件到状态赋值的链路、图片创建/复用时机、初始值来源、产品期望及旧包截图。只有`@State radius`声明而没有写入点，不足以证明一定变化；对象嵌套值、属性修饰器及父子传递也不能因没有`@State`字样就排除。

可排除固定圆角且不会变化的Image、仅其他组件使用圆角、低target的本条行为；没有实际配置或动态来源时记录证据不足，不能把命中整体标成无需适配。

## 受影响与不受影响示例

以下为组件`build()`内的调用片段，`this.avatar: Resource`为组件已有图片资源字段，`radius`是现有状态，点击将其从10改为30：

```ArkTS
Image(this.avatar).width(80).height(80).borderRadius(this.radius)
Text(`当前设置：${this.radius}`)
```

若业务要求文字继续显示新设置但头像始终保持10，受影响点仅是图片绑定。最小调整示意：

```ArkTS
// avatar仍是原资源；仅图片圆角固定，radius的状态装饰器及其他使用者保留。
Image(this.avatar).width(80).height(80).borderRadius(10)
```

不受影响例：Image始终`.borderRadius(10)`，没有修饰器覆盖；或动态变圆就是已明确接受的交互，回归通过后无需修改。不能为所有图片批量写10：各图片原始圆角、单位和首次创建数据可能不同。

## 最小方案与边界

先确认希望保留固定外观还是采用动态行为。固定外观只替换受影响Image的参数，使用其真实初始值或稳定配置；初始值随头像类型变化时，应为本次图片实例保存对应初始输入，不能硬编码全局常量。动态外观符合产品预期则保留绑定并补验证。

不删除被其他视图、监听或计算使用的状态装饰器，不停止整个状态的赋值，不添加无依据的运行系统版本分支，也不把其他组件的圆角更新都视为本条触发。移除状态装饰器与保持图片旧圆角不是等价操作。

## 验证与证据缺口

对同一图片依次验证首次显示、状态变化、切换资源、离页返回/复用。固定方案要求图片保持各自正确初始圆角，文字等其他依赖状态的视图仍正常刷新；接受动态行为时核对每一状态的圆角和过渡。保留旧、新包与对应target、设备版本、操作步骤和截图。

本案例仅核查官方资料和SDK声明；真实工程编译、设备操作、截图对照均未执行。未提供写入链、实例创建时机或外观期望时，结论为证据不足，待补齐后再决定是否修改。
