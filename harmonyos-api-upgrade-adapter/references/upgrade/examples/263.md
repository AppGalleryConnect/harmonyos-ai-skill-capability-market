# 263-bindSheet半模态面板视觉样式增加

## 来源与版本

身份：扫描Rule ID `263`。

[完整官方章节](../../changelogs/5.0.2(14)/ux-style-and-effect-changes.md#bindsheet半模态面板视觉样式增加)明确 targetSdkVersion≥5.0.2(14) 时生效；policy归属5.0.2(14) Beta1，本地标题映射确认扫描 RuleID 为263。bindSheet起始API11不等于本次样式门槛。

本机 SDK 26.0.0.105 Release 的 `ets/component/common.d.ts` 声明 `bindSheet(isShow: boolean, builder: CustomBuilder, options?: SheetOptions)`、`SheetOptions.preferType?: SheetType`，真实枚举为 SheetType.BOTTOM / CENTER / POPUP。preferType 在API11的类型限制与API12后的完整SheetType支持已有注释，本案例不凭当前SDK推导所有旧版本能力。

## 旧新行为

官方限定设备宽度在600–840vp间，且preferType=SheetType.POPUP：旧为居中弹窗，新为跟手弹窗。该区间内默认仍为居中，可用CENTER明确表示居中，BOTTOM表示底部，POPUP表示跟手。不能把所有bindSheet或所有POPUP都改成CENTER。

“600–840vp间”是原文描述；原文未用不等式精确定义端点，本案例不新增端点包含性结论，也不将设备宽度直接替换为任意容器宽度。

## 影响条件与工程核查

记录真实target、设备/显示宽度的vp证据和窗口模式，再追踪SheetOptions的实际构造、preferType分支、封装覆盖及绑定锚点。检查业务究竟依赖居中位置还是需要新增跟手样式；多窗口/折叠场景不能从设计稿像素或模拟窗口宽度猜出设备条件。

非POPUP、明确区间外或原target不触发时，说明排除依据；现有POPUP改为跟手且业务已需要该效果时可保留原码。未给实际宽度、单位/密度转换或动态preferType时，列具体证据缺口。

## 受影响与不受影响示例

以下是已有控件的bindSheet属性链，builder和显示状态维持原工程，业务需要保留旧居中：

```ts
.bindSheet(this.showSheet, this.sheetContent, {
  preferType: SheetType.POPUP
})
```

在已核实720vp且达到门槛时，最小候选是本调用改为 `preferType: SheetType.CENTER`。已显式CENTER、BOTTOM，或实际设备宽度为500vp的POPUP，均不能据本条一律修改。

## 最小方案与边界

只对需要保持居中的命中调用显式CENTER；保留POPUP可表达跟手需求，BOTTOM仅用于业务原本需要底部的场景。不删除锚点、不改其他弹窗、不给整个应用统一配置preferType。若相同SheetOptions还服务区间外设备，先评估共享改动的影响，必要时缩小到原业务分支。

官方允许居中时不设置preferType，但省略可能改变共享选项与其他设备上的结果；优先保留工程已知语义，并按[target升级兼容](../upgrade-compatibility.md)核对真实多系统组合，不捏造新SDK门槛。

## 验证与证据缺口

在确定区间内如720vp对比原/最终包的面板位置、锚点跟随、点击区域与关闭行为；区间外、600/840附近及动态尺寸变化需分别取证，端点待实测，不能把测试计划写成已证实结果。编译、设备运行、截图均未执行。
