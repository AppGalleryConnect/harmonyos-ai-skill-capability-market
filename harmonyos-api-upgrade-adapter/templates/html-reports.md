# HTML 报告模板

三份HTML保留完整内联样式、默认可见结论及折叠明细，不依赖脚本、网络或外部CSS。模型只维护当前事实，固定工具负责投影和渲染，不编写临时生成脚本。

| 模板 | 内容 | 入口 |
| --- | --- | --- |
| [废弃 API 迁移](deprecated-report.html) | 迁移结果、兼容、复扫和验证 | D11，report render |
| [API 行为适配](upgrade-report.html) | 评估、方案决定、实施与独立验证 | U09，report render |
| [行为测试](upgrade-test-report.html) | 真实用例、断言、图片及比较 | U08，runtime report |

## 固定报告命令与输入

```console
node "<skill-root>/scripts/report/cli.mjs" render --task "<绝对taskFile>" --mode upgrade
node "<skill-root>/scripts/csv/cli.mjs" verify --task "<绝对taskFile>" --project "<工程>" --mode upgrade
```

废弃将mode改为deprecated。新流程不运行report prepare、不传--data，不维护报告JSON。工具按任务索引读取全部参与工程，包括失败和未开始项；同一次读取原扫描、分组、进度及真实证据，共同生成结果CSV和功能唯一的api-adapt-report.html。HTML 和 CSV 共用逐行判断。CSV 将处理说明输出为单行，HTML 完整依据保留原段落。

| 事实 | 唯一维护位置 |
| --- | --- |
| 原始列、行序、重复行及来源 | 原扫描CSV和伴随扫描JSON |
| DevEco 覆盖条目的行为变化与 target 隔离 | 按变更标识、精确版本和扫描来源核对内置官方正文；正文与索引纳入报告来源校验 |
| 其他条目摘要及业务判断 | group.changeSummary：before/after/targetIsolation/business/proposal |
| 行为HTML业务概括与逐行简述 | group.changeSummary.business、rowResults.reportSummary；仅用于展示，不替代完整依据 |
| 每行分类、依据、兼容、实际差异与业务待办 | group.rowResults，评估字段与resolution分开 |
| 工程版本、配置实施事实 | progress.versions、configurationImplementation |
| 实际批准或不实施决定 | progress.decisions.repair及只读方案快照 |
| 构建、设备状态与证据 | progress.verificationSources引用真实回执和审计，不手填第二份通过状态 |
| 行为报告的针对性测试建议 | progress.testSuggestions，可选字符串数组，由主agent在U09填写 |
| DevEco规则包未覆盖条目补充处理 | 扫描 JSON 的 officialComparison 提供事实，progress.decisions.ruleGapReview 保存是否补充评估的决定，progress.ruleGapReviews 保存逐条评估、批准及修改 |

业务说明取 changeSummary.business，兼容依据取逐行 compatibility，缺口从实际状态和待办汇总。关键决策从已登记方案和明确用户答复生成，旧 keyDecision 字段仍可读取。

行为验证通过[验证引用入口](assessment-results.md#工程级验证引用)一次登记；状态从receipt.json或runtime audit读取，并核对证据摘要、覆盖范围及相关输入。缺失、变化、失败和未执行各自表达，不继承旧PASS。不实施方案是正常评估交付，原分类保留且处理结论为未实施，不执行修复构建或设备验收。

## 填写与阅读

1. 评估agent填写独立草稿，由主agent接收；主agent填写跨组方案与真实决定，修复后只更新对应行处理结果。评估及批准快照是只读证据，不是第二套当前状态。
2. report render保留模板完整head和内联CSS，仅替换adapter:report内容区域。生成前后核对输入快照、完整rowId、全部重复行和逐行四列。相关输入变化时停止发布；进度同步失败非零返回，保留产物供同一输入重试。
3. 已登记哈希且字节未变化的工具自有结果可以更新。用户修改过或来源未知的CSV/HTML自动另存；回执和progress.delivery保存实际路径，报告链接、runtime和verify跟随当前引用。spec链接使用实际repair.plan。
4. 升级报告页尾展示北京时间的报告生成时间，精确到秒。同一内容重试沿用已生成文件的时间，新内容记录本次生成时间。交付哈希校验实际文件的完整字节。
4. 所有文本转义，路径按HTML所在目录生成相对URL并编码中文、空格和#；跨盘或资源缺失如实保留，不伪造链接。按下节用浏览器验收桌面、窄屏、折叠详情和打印。

测试报告使用runtime report生成，保留runtime:report内容区域。内部存档与交付版链接按各自目录计算。带截图CSV使用runtime csv的任务入口，不传逐行结果JSON；后续统一发布继续从同一审计引用取得截图。

## 浏览器预览与视觉验收

使用命令回执中的实际交付路径，包括另存版本。浏览器工具无法打开本地文件时，运行预览并在浏览器打开返回的 URL。

```console
node "<skill-root>/scripts/report/cli.mjs" preview --task "<绝对taskFile>" --html "<实际交付HTML>"
```

预览只读服务任务目录内的报告和相对资源，监听本机 `127.0.0.1` 的空闲端口。检查完成后按 Ctrl+C 关闭，也会在五分钟后自动停止。任务目录之外的链接沿用原报告中的地址，需按原路径单独核对。

- 桌面窗口检查总览、列宽、换行和证据链接。
- 约 375 CSS px 的窄屏检查表格滚动区域和文字可读性。
- 展开和折叠详情，检查对应内容及展开状态。
- 打开浏览器打印预览，检查分页、逐行明细和应展开的依据。

逐项记录实际检查结果。浏览器无法访问预览地址或缺少窄屏、折叠、打印能力时，将对应项记为未验收，保留可交付的 HTML。预览启动回执、结构校验和来源核对各自提供独立证据。

## 统计与结论

- **废弃**：六类处理状态及重复行完整保留，迁移、构建、复扫和用户要求的单次设备验证分别报告，不引入before/after要求。
- **行为**：范围外在交付时归入无需适配，无需/可选/必须适配和待分类合计等于原始逻辑行数。处理结论为无需适配、已适配、待决策、未实施，与评估分类分别统计。评估交付完成、方案实施、验证通过彼此独立。
- **布局**：工程总览按工程名称、target升级、compatible、原始扫描结果、适配情况、编译构建、运行情况排列。顶部与总览使用同一版本记录。compatible 只显示版本值或前后版本变化。配置实施事实由进度保存。工程正文按实际出现的适用性排除、DevEco 规则包覆盖条目（仅导入原表时为 CSV 导入条目）、未覆盖条目补充处理及独立验证连续编号，变更条目使用四级标题。共享修改批准由 spec 和进度保存。
- **默认阅读**：工程总览下每工程展示最多五项已实施改动和三条待处理提示。改动按变更聚合，补充评估按项计数。关键决策、工程章节及单项完整依据逐层展开。摘要使用当前任务的结果和已有简述，证据入口指向可见的章节标题。
- **扫描证据**：超时、失败或部分完成的扫描缺口在遗留事项中各列一次。同批次证据链接接在对应条目末尾，耗时和跳过文件在证据中查阅。按工程适用性排除的变更在工程正文展示规则 ID、官网链接、排除原因和适用范围。配置依据由扫描证据保存。覆盖缺口与适用性排除各自独立于原始 CSV 行和逐行待办统计。
- **C/C++ 文本候选**：仅在有候选时，紧跟工程正文「DevEco 规则包覆盖条目」的正式评估明细，默认折叠。按模块列出规则、API 和代码位置，供人工核对。候选独立于原始 CSV、评估与审批统计，遗留事项仍仅展示实际缺口和证据链接。
- **逐行明细**：每个完整rowId单独一行，六列为rowId、代码位置、评估分类、处理结论、处理说明、后续事项，列宽20%/18%/7%/7%/32%/16%。处理说明优先显示模型填写的一两句reportSummary，原段落在同单元格“完整依据”折叠展示；缺少简述或决定过期/待复核时回退全文。业务与触发仅用本组business概括，不拼接逐行理由。原CSV、完整依据及行序不变，不截断、不合并重复行，打印展开全部行及依据。
- **遗留事项与测试建议**：行为报告在全部工程评估与修复之后用一个卡片按工程分组，两部分上下排列，默认收起并标注条数，打印完整展开。遗留事项合并实际缺口、完整逐行后续事项及旧输入nextSteps，仅去除同一工程内完全重复的内容，保留关联行身份。扫描证据链接随对应条目展示，官网链接和独立验证证据在正文对应位置展示。没有遗留记录不代表验证通过。
- **批准文案**　四类评估卡片分别补充非零的获批修复、接受新行为行数，按工程与 rowId 去重。关键决策按工程与变更展示已答复的方案说明、决定及覆盖行数，完整答复与来源折叠保留。共享配置、待答复及过期决定留在对应记录中。
- **官方摘要**　DevEco 覆盖条目展示明确的官方前后对照原文或对照表。官方仅有变更影响时保留官网链接与 target 隔离信息；来源无法核对时标明「官方原文待核对」。工程触发及兼容判断留在详情。
- **建议与验收**：主agent根据当前评估、实际差异和验证范围在progress.testSuggestions填写测试对象、具体操作、预期结果及适用设备或版本，覆盖受影响的功能、视觉和兼容场景，不套用其他工程的页面或版本。存量告警归入遗留事项。建议不作为逐行next、不增加待办统计、不触发设备操作，也不代替真实验收；缺少建议如实显示。更新建议后重新render再verify，不维护报告JSON。
- **边界**：零行仍交付表头和报告，不表示扫描全覆盖或测试通过；待答复、证据不足和扫描外修改单列。未成功完整构建不能声称修复已验收，未实施不能说无需修复。pendingCount、未决、后续事项和复核数量均按回执分别报告，不能为归零而清证据缺口。
- **规则包未覆盖条目**在存在确认未覆盖条目时单列一章。用户选择跳过时，只显示未覆盖数量和「用户选择跳过补充评估」。等待答复时显示待决定。已评估条目展示来源、分类、依据、方案或决定、实际差异及下一步。比对来源变化时标记待复核，补充处理的统计独立于扫描覆盖和原 CSV。

## 旧调用兼容

历史prepare --output及render --data继续可用，[旧数据示例](adapt-report-data.json)只用于独立/旧输入。当前group/progress已建立的字段优先，旧配置、变更背景、逐行结果或验证状态冲突时拒绝；不能借旧JSON覆盖当前事实。旧输入字节仍归档作来源核对，新流程不产生该输入或归档。

verify检查原始来源、当前投影、CSV、报告及其来源摘要。MATCH只说明交付一致，不表示业务判断或设备验收已通过。真实验证引用变化或来源过期不能沿用旧交付结论。
