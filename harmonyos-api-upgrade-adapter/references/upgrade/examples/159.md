# 159-CanvasRenderingContext2D方法传NaN和Infinity值后执行的其他绘制方法由不绘制变更为正常绘制

## 来源与版本

身份：扫描Rule ID `159`。

依据[官方完整章节](../../changelogs/5.1.0(18)/os-api-behavior-changes.md#canvasrenderingcontext2d方法传nan和infinity值后执行的其他绘制方法由不绘制变更为正常绘制)（302–359行）。5.1.0(18) Release明确仅应用`targetSdkVersion ≥ 5.1.0(18)`生效，涉及CanvasRenderingContext2D、OffscreenCanvasRenderingContext2D、Path2D。起始API Level 9不是本次target门槛。

本地API 26 SDK `openharmony/ets/component/canvas.d.ts:441–489`确认lineTo/moveTo的number签名及API 18前后非法值处理；1374的globalAlpha、2018的lineDashOffset为属性而非方法；CanvasRenderer继承CanvasPath（1304行），两个上下文继承CanvasRenderer（2787、3098行），Path2D继承CanvasPath（618行）。`build-tools/ets-loader/node_modules/typescript/lib/lib.es2015.core.d.ts:227`声明`Number.isFinite(number: unknown): boolean`。

## 旧新行为

旧行为：路径方法number参数出现NaN/Infinity会导致整条路径无法绘制；缩放、旋转、平移、矩阵变换等被污染后，后续有效绘制也可能无法绘制。新行为：非法输入对应操作不生效，其他有效操作继续绘制。官方同时列出globalAlpha及lineDashOffset：非法虚线偏移的旧实线现可按虚线绘制，不能漏掉这些属性赋值。

不是所有Canvas API共享同一种非法值语义；只按官方表及准确SDK声明分析。该章列名为ellipse等接口的细节需按工程实际声明核对，不推导不存在的方法。有效命令能绘制是容错改进；只有业务依赖“非法值让整批图形消失”或出现不合预期的残缺连接时才需修改。

## 影响条件与工程核查

先核对target，再查路径、变换、alpha和虚线偏移来源，覆盖计算除零、解析失败、缺数据、数组越界以及外部输入；不要只检索字面量NaN/Infinity。追踪一批图形的beginPath、状态保存恢复、stroke/fill与多个子路径，识别非法值之后仍有效的命令，以及业务希望“跳过单点、分段”还是“整批不绘制”。

证据应包含完整数值计算、异常样本、实际绘制序列和画面期望。所有传入值由有限数校验保证且合法样本回归通过，可无需修改。出现非法值但希望接受新容错，也可无需修改并记录验证。只有`drawChart(data)`封装而数据和实现缺失，属于证据不足；不能因没有NaN常量就排除。

## 受影响与不受影响示例

以下`ctx`是已准备绘制的CanvasRenderingContext2D，代码位于一次绘制函数内；业务规定任一坐标无效时整条轨迹不显示。旧代码靠lineTo(NaN, ...)隐式阻断：

```ArkTS
ctx.beginPath()
ctx.moveTo(100, 100)
ctx.lineTo(NaN, 100)
ctx.lineTo(200, 200)
ctx.stroke()
```

新行为会按有效点绘制，违背整批失败规则。应在产生任何本批绘制副作用之前检查全部必需参数。下例`x1/y1/x2/y2`是已算出的两个轨迹点，片段在该批绘制函数顶部：

```ArkTS
if (!Number.isFinite(x1) || !Number.isFinite(y1) ||
    !Number.isFinite(x2) || !Number.isFinite(y2)) {
  return
}
ctx.beginPath()
ctx.moveTo(x1, y1)
ctx.lineTo(x2, y2)
ctx.stroke()
```

无需修改例：所有点/变换均有有限数校验；或产品本来允许跳过无效命令并接受新路径结果，设备验证通过。简单过滤点可能把缺口两端连起来，若业务要求断线必须显式分段，不能当作等价修复。

## 最小方案与边界

整批无效策略在提交路径/变换之前做有限数校验并退出该批；不要在stroke之后才return，因为旧内容已产生。若已有上一帧内容，是否清理应按真实产品契约处理，单纯return不等于清空画布。分段策略在缺失点处分开路径；接受容错则保留绘制，只修正确实错误的数据来源。

禁止把非法值都改成0，会画出不存在的点或改变矩阵；只用`isNaN`会漏Infinity；`if (!x)`还会误拒合法0。不能通过把target降回17或给其他绘制方法继续注入NaN维持隐藏逻辑。矩阵、globalAlpha和虚线偏移应按各自语义校验，不能将本条扩张成统一Canvas参数重写。

## 验证与证据缺口

分别测试NaN、正负Infinity、合法0、空数据、部分缺点、非法矩阵、globalAlpha和lineDashOffset，观察后续有效绘制、路径连接、虚线、上一帧残留及状态恢复；同时覆盖屏幕Canvas、离屏导出和Path2D使用。保存输入值、绘制序列、target及对应截图。

本案例真实编译、设备绘制、导出与图像对照均未执行。缺数值来源或业务整批/分段期望时记录证据不足，不能把官方“无需适配”直接当作工程无风险结论。
