# 373-修复blendMode接口离屏模式会影响组件设置的不透明度的问题

## 来源与版本

身份：扫描Rule ID `373`。

[完整官方章节](../../changelogs/5.1.0(18)/os-api-behavior-changes.md#修复blendmode接口离屏模式会影响组件设置的不透明度的问题)位于5.1.0(18) Release，明确targetSdkVersion≥5.1.0(18)生效；标题映射确认扫描RuleID为373。blendMode起始API11不等于此修复的门槛。

本机SDK26.0.0.105 Release的 `ets/component/common.d.ts` 核实 `blendMode(value: BlendMode, type?: BlendApplyType)`、BlendApplyType.OFFSCREEN / FAST及 `opacity(value: number | Resource)`。opacity有效范围0–1，父子会相乘。SDK还注明BlendMode.NONE时BlendApplyType不生效，不能只见OFFSCREEN字样就判定离屏实际开启。

## 旧新行为

组件有效使用blendMode离屏模式且同时具有opacity=A时，旧实际不透明度为A×A，新为A。对于0<A<1，新效果更不透明；A=0或1时这项数值修复没有差异。是否要恢复A²取决于原业务视觉目标，不是看到opacity就必须增加另一层。

## 影响条件与工程核查

读同一组件的完整属性链、modifier、资源与动画状态，核对blend模式、apply type、最终A及父子透明度。检查祖先/兄弟/子节点的混合边界、背景和已有补偿，确认旧视觉是否确实依赖重复乘算。FAST、未设置opacity、有效A恒为0/1或已无离屏效果的NONE可按证据排除本条差异。

动态A或混合参数、封装实现未给出时列缺口，不统一套0.5。多个节点共用父容器时，父容器透明度会连带改变其他节点，必须保留无关内容。

## 受影响与不受影响示例

以下为新行为环境下局部候选：原节点A=0.5、旧目标实际0.25，业务要求保留旧效果，且无其他补偿。保留混合参数，只将该节点自身opacity改为0.25：

```ts
Stack() { /* 原受影响节点的内容 */ }
  .blendMode(BlendMode.SRC_OVER, BlendApplyType.OFFSCREEN)
  .opacity(0.25)
```

这是对官方“手动调整原本不透明度”的单节点方案推导，仍需实际合成验证；不表示所有嵌套混合场景都能仅凭公式证明等价。有效A恒为1的离屏组件，或明确FAST的A=0.5组件，本条无需改透明度。

## 最小方案与边界

若业务接受修复后准确的A，保留原码并记录决定。需要A²时，先考虑局部调整本节点的实际输入；动画/状态表达式需保持原变化关系，不能只改某个静态终值。只有必须使用专属容器且已核实混合边界、命中节点和其他内容隔离时，才评估额外opacity层；禁止统一在共享父容器加opacity补偿。

官方例子含父子两个0.5，是示例而非全局操作模板。补偿在旧运行行为下可能再次平方，不能把新行为专用的0.25无条件部署到全部历史环境；按[target升级兼容](../upgrade-compatibility.md)核对真实系统/target组合和最小分支，不猜系统API门槛。

## 验证与证据缺口

原包/最终包在固定背景上比较实际命中节点及未修改兄弟节点，覆盖A=0/0.5/1、真实动画状态、混合模式和嵌套边界；检查没有额外补偿或亮暗变化。真实编译、设备截图与合成实验均未执行，公式推导不等于像素等价已验证。
