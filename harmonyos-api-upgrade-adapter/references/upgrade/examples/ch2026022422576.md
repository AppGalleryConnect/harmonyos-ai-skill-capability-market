# CH2026022422576-组件的阴影模糊半径规格变更

## 来源与版本

身份：扫描Rule ID `CH2026022422576`。

[完整官方章节](../../changelogs/26.0.0/beta1-changes-for-all-apps.md#组件的阴影模糊半径规格变更)位于 26.0.0 Beta1，明确仅在应用 targetSdkVersion≥26.0.0 时生效。shadow 起始 API Level 7 与本次行为门槛分开记录。扫描 RuleID 为 CH2026022422576；本地标题映射未收录，身份由 DevEco 规则包核实，不能用 policyId 代替扫描 ID。

本机准确 SDK 为 HarmonyOS 26.0.0.105 Release；`ets/component/common.d.ts` 的 ShadowOptions 声明 `radius: number | Resource`、`offsetX?: number | Resource`、`offsetY?: number | Resource`，偏移默认 0、单位 px。声明注释仍称负数按 0 处理，与本条 API26 官方新行为存在文字差异，应保留差异并实测，不能把注释当作否定官方变更的依据。

## 旧新行为

旧行为中 radius=0 和负数均无阴影。新行为中 radius=0 存在阴影但无模糊，负数无阴影。偏移会让不带模糊的阴影明显露出；不能把“未设置偏移”当作 radius=0 语义完全未变的证明。

官方范围包含通用 shadow 的全部阴影类型，以及 ActionSheetOptions、AlertDialogParam、CalendarDialogOptions、CustomDialogControllerOptions、DatePickerDialogOptions、TextPickerDialogOptions/TextPickerDialogOptionsExt、TimePickerDialogOptions、SheetOptions 的 shadow；还包括 PopupOptions/CustomPopupOptions/PopupCommonOptions.shadow、promptAction 的 ShowToastOptions/ShowDialogOptions/CustomDialogOptions.shadow、TabSegmentButtonV2/CapsuleSegmentButtonV2.itemShadow 和 SymbolGlyph.symbolShadow。Text.textShadow 明确不发生本条变更。

## 影响条件与工程核查

先核对应用打包 target、运行系统与真实 SDK，再沿命中入口读完整属性链、样式封装、资源值、状态分支和组件类型。记录最终 radius、offsetX/Y、阴影类型、背景/裁剪、旧视觉目的。搜索范围不能只限 `.shadow(`，也要追到弹窗选项、itemShadow 和 symbolShadow；资源或动态表达式要追到实际值。

radius>0 不涉及本次零半径边界；负值原本与现在都用于无阴影。仅 textShadow 命中可排除。radius=0 无偏移时，组件背景/轮廓可能遮住阴影，需区分“看不出差异”与“规格未变”。是否修改以业务是否仍需无阴影为准。

## 受影响与不受影响示例

下面是原组件的局部属性链，业务把零半径作为关闭阴影，同时保留偏移：

```ts
Column() { /* 原内容 */ }
  .shadow({ radius: 0, offsetX: 20, offsetY: 20 })
```

满足新行为门槛时会出现无模糊阴影。相同对象用于 textShadow 则不受本条影响；radius=12 的正常模糊阴影也无需为本条改为负数。若 radius 来自未提供的资源文件，只能先列证据缺口。

## 最小方案与边界

已确认需要继续无阴影时，仅将对应 ShadowOptions.radius 从 0 改为 -1，保留偏移、颜色和原业务；不要统一删除所有 shadow 调用。业务原本需要硬边阴影时保留 0 即可。排除的 textShadow 不套用 -1 方案。

多系统行为按[target 升级兼容](../upgrade-compatibility.md)核查；不能把本条 target 门槛当作系统接口新增门槛，也不能推测负数在所有历史 SDK、所有非官方列举接口上均等价。实际工程 SDK 的类型/注释冲突需要单独记录。

## 验证与证据缺口

在原包和最终包对应系统上，覆盖 radius=-1/0/正值、偏移为 0/非0，以及命中组件实际背景与裁剪；核查“需要无阴影”和“需要硬边阴影”两种业务。构建只能验证类型与工程产物，截图/视觉检查证明表现。本案例只做资料和声明核对，真实编译、设备运行、截图均未执行。
