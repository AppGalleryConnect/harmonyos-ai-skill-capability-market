# 198-修复zIndex接口会影响组件在3D变换中的透视效果的错误行为

## 来源与版本

身份：扫描Rule ID `198`。

依据[官方完整章节](../../changelogs/5.0.2(14)/os-api-behavior-changes.md#修复zindex接口会影响组件在3d变换中的透视效果的错误行为)（579–647行）。变更发布于5.0.2(14) Beta1，明确仅应用`targetSdkVersion ≥ 5.0.2(14)`生效；接口起始API Level 7。

本地API 26 SDK的`openharmony/ets/component/common.d.ts:20213–20227`定义zIndex为兄弟组件叠放顺序；19715–19736的translate支持Z向移动造成近大远小；4175–4210定义TranslateOptions的x/y/z为`number | string`，19876行确认rotate参数接口。SDK对Z数值单位的注释存在不一致（字段写px、通用方法写vp），本案例不据此推导像素换算，按真实工程单位和设备基线校准。

## 旧新行为

旧实现中zIndex与translateZ耦合，3D变换时改变zIndex会同时改变透视；新实现中zIndex不再影响近大远小，但仍承担叠放排序。目标SDK低于14时本条隔离行为保持旧规格。

风险是原先把层级值兼作深度值的页面视觉变化。仅看见zIndex和rotate共存不能推断用户需要保留旧透视；需核对设计及原包。Z平移与层级排序有不同职责，不能将两个数值机械复制。

## 影响条件与工程核查

先核对真实target，再查`.zIndex(`与同节点及祖先链的rotate、translate、transform和动画。追踪zIndex动态来源，是否表示“当前卡片突出”、仅解决遮挡，或被有意用来调近大远小。属性修饰器、父节点3D变换和共享组件也需核查，不能只检索同一行。

保存组件完整属性链、兄弟布局、层级值变化、已有Z平移、旧截图/设计目标。若仅普通2D叠放且无3D透视依赖，可无需修改；已通过Z平移实现目标透视且验证没有依赖额外耦合时亦可无需修改。有旋转和zIndex但缺旧效果与业务预期时，属于证据不足，不能批量加translate。

## 受影响与不受影响示例

以下为卡片build片段，`this.cardTitle: string`是组件已有标题字段；产品用“选中时改变zIndex”得到更靠近观察者的效果：

```ArkTS
Text(this.cardTitle)
  .rotate({ y: 1, angle: 45 })
  .zIndex(this.stackOrder)
```

在已确认需要保留透视后，拆开层级和深度，`depth`是按原视觉基线校准的Z平移值：

```ArkTS
Text(this.cardTitle)
  .rotate({ y: 1, angle: 45 })
  .zIndex(this.stackOrder)
  .translate({ z: this.depth })
```

不受影响例：二维Stack中用zIndex(2)让角标覆盖图片，没有3D变换；或已有独立Z平移并且旧包/新包对照确认目标效果一致。不因使用zIndex就删除它，否则可能破坏正确遮挡关系。

## 最小方案与边界

仅对确实依赖旧耦合的节点新增或修正Z平移，保留业务需要的zIndex。已有x/y/z平移时合并到同一真实属性链，避免后一次调用覆盖原值。原代码已有Z深度时，应校准总效果，不能再无条件增加一份。

官方样例的zIndex 200对应改用z向平移66只是示意，不是通用换算公式；不能全库把zIndex数值复制给translate.z。要同时校准旋转中心、父变换、大小和遮挡，避免通过改层级补透视引入点击/覆盖问题。不要为低target盲目添加会与旧耦合叠加的补偿，也不自造运行系统版本隔离。

## 验证与证据缺口

对相同页面在多个层级/深度值下对照近大远小、角度、遮挡、裁剪和交互命中；覆盖切换选中卡片、动画过程、返回页面及屏幕尺寸变化。记录原、新target、设备密度、截图及校准值由来，不能只检查编译。

本案例真实编译、设备和透视截图比较未执行。缺旧视觉基线、变换祖先链或目标SDK时记录证据不足；SDK单位注释歧义也必须在具体设备中核对，不能宣称数值等价。
