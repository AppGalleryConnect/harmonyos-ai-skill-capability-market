# 行为适配方案模板

由[U05](../references/upgrade/upgrade-workflow.md#u05-汇总-spec-并取得确认)在全部评估接收后，通过[固定方案工具](spec-results.md)生成。spec是评估与方案展示、用户决定的依据，实际实施和验证在当前状态及总报告展示。

## 自动生成部分

- 从group.changeSummary读取旧新行为、target隔离、方案及主要取舍。
- 从rowResults生成完整原始行、评估分类、依据和兼容分析，重复行分别保留。
- 从明确方案项读取动作和完整rowIds，补充物理文件、调用位置、API定义、原始行数及独立代码位置数；不把位置数自动称为业务调用数。
- 从实际决定记录生成确认区，区分待答复、批准实施和明确不实施；纯评估允许没有修改项，不能为生成spec编造修改。

主agent不在narrative再次抄写这些字段，也不直接编辑生成的确认区。

## 主 agent 填写部分

方案JSON的narrative仅补充跨组约束、成本和冲突协调；items/sharedItems提供明确方案ID、动作、说明及完整原始行引用。内容包括：

- 工程、product、范围、原/目标target及保持的compatible；配置值以progress和真实工程为依据。
- 同文件、公共helper、配置和跨文件接口的合并方案、影响范围和修改归属；冲突未解决不进入修复。
- 保留原体验的成本及替代选择、已有证据不足和待业务决定部分。
- 选择实施时的验证方式和必要覆盖；按顺序展示“仅编译构建，不运行设备测试（推荐）”“修改后设备验证（Beta）”“前后对比验证（Beta）”，说明设备选项处于试用阶段，已有明确选择时沿用。仅选择设备测试时确认范围，只有对比模式在相关修改前先有效归档 before 包。用户只评估不实施时不启动这些修复验收步骤。

用户可以全部实施、部分实施、明确不实施或暂未答复。通过record-decision登记真实答复，不从最初“自动适配”的请求推断具体批准。未答复保留待决策；明确不实施保留原评估分类，结果为未实施，仍交付原扫描、spec、CSV和HTML。

方案发生实质变化时使用新方案ID，只核对受影响决定；实际修复必须受明确批准范围约束。不在spec回填已修复或验证通过来维护第二套执行状态。
