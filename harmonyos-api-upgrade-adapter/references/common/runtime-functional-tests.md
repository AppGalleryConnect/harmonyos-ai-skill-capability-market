# 功能取证与设备验证方法

各功能主流程只加载适用小节，验证范围由实际用户要求决定；本页不新增设备授权、通用接口版本匹配或自动最低系统验收。行为使用内置分层测试工具，先读真实help；依赖缺失记录环境阻断，不临时改用其他执行器。废弃保持原单次验证范围。

## 通用功能取证

明确实际HAP、设备/系统、当前源码与配置及所选rowIds，记录用例、前置数据、操作、预期与实际值/回调。所选NO_CHANGE条目也验证正常功能，未选和缺口不缩小原始行分母。组件截图不能替代实际返回值、回调或持久化；Dialog取消不证明确认按钮回调，同页不代表覆盖所有原始行。

HDC目标需核对连接类型、端口及实例映射；歧义或不在线停止该设备操作，不默认第一台或切换其他实例。真实冷启动有界等待，不同步等待长期Emulator进程退出。工具缺失时保留具体UI能力缺口，不凭Canvas等实现猜测无法操作。

### 实际执行与采集

逐用例保存完整命令、退出码、操作序列、实际值/断言、采集时间和图片/日志；可在轻量分组记录中记录。既不以外部脚本退出0，也不以图片存在直接标功能通过。模型无法读取图片或视觉工具中断时视觉结果未验证，不冒充产品缺陷。

固定密码输入/确认/Toast等场景限定Dialog容器、控件类型和唯一可见目标；不能把多个TextInput或重复文案串错。500ms防连点和1500ms Toast使用设备实际支持的连续操作及时捕获；主机多次往返导致瞬态消失时保存耗时与受阻事实，不放宽预期，不把另一次触发的截图当同一次证据。

非视觉功能可没有截图，但必须有真实功能证据。图片只关联其实际用例和原始行；起始图、诊断图不能填满无关业务行。若用短路径副本，保留原来源与哈希，真实格式是JPEG就使用.jpeg，不把任意文件改扩展名装PNG。


## 废弃单次设备验证

仅按用户明确要求验证当前构建产物，不采集修改前阶段，不要求比较或基线降级选择。实际功能与所请求设备范围分别报告；没有要求设备时保持NOT_RUN，不主动询问或启动。

下列矩阵仅用于废弃任务已要求的兼容设备范围，按真实执行列通过/未验证，不为行为增加最低系统任务，也不自动扩大当前设备授权。

### 废弃设备覆盖参考

已授权设备验证时，按每条变更实际门槛选择下列组合，记录设备 API、包的 `targetAPIVersion`/`minAPIVersion`、相关 ABI、入口与原始 rowIds。版本含义和规则见[共用兼容指南](compatibility.md)，不按 ROM 名称或静态型号推断覆盖。

| 验收位置 | 必须取得的证据 |
| --- | --- |
| 最低 compatible | 本次包可安装、冷启动/初始化成功，低版本业务及回退实际可用；库加载也在此验证 |
| 接口边界 | 在支持范围内覆盖门槛以下最近可用版本与门槛版本或其上首个可用版本，分别触发旧/新路径；不同门槛分别核对，不能只测 target 对应系统 |
| 新接口实际调用 | 高版本设备真正执行到新增方法/参数/回调并验证结果；API 刚引入的边界与所选编译 SDK 对应系统的路径均需考虑，仅启动不算覆盖 |
| HAR/集成态 HSP | 宿主实际消费本次依赖、完成初始化并走到库调用；HAR 按真实宿主 target，HSP 按各包 target 核验，保留失败处理证据 |
| C/C++ 与 UI 隔离 | 相关 ABI 的加载/链接及新旧调用路径；UI 的两个组件实现、状态更新、复用与生命周期分别验证 |

若门槛以下已低于包的安装下限，记录该组合不在支持范围及依据；缺少最低版本、边界设备、宿主或某 ABI 时列出具体未验收项，不能以高版本冒烟、弱引用编译通过或一台设备替代。未要求设备验证时保持 NOT_RUN，并将这些组合列为建议验收，不擅自启动设备。

该矩阵结合 2026-08-28 [历史版本兼容验证指导](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/compatibility-verification)与[原生兼容验证要求](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/c-api-compatibility-warning)提炼；实际执行仍按下面的阶段包与功能证据规则。


## 行为前后对比

行为设备验收按以下职责链执行，不把本页的原则说明当成已生成测试能力：

- U05确定选择后，在修改前按[白盒理解](runtime-whitebox.md)从原始CSV调用点保存来源、原始上下文和route-map.json。每个来源和逻辑行单独保留，不能以README或页面清单替代选中范围。
- 仅对比模式按[阶段包方法](verification.md#行为前后对比)在修改前真实构建并按[契约](runtime-contracts.md)归档原始before。归档不是设备实测；有效原包归档后，设备不可用不阻塞获批修复。模拟器直接使用实际未签名HAP，不自动生成证书或签名。
- 修复完成后按[测试设计](runtime-case-generation.md)结合CSV、原始白盒事实和获批spec，依次生成test-spec.json、test-cases.json、Hypium JSON 操作清单，校验并冻结内容快照。相关阶段包、用例、操作清单和采集点不得执行时临时替换；默认使用两个包共有入口，不给after新增测试源码后假设before支持。
- 通过[工具契约](runtime-contracts.md)执行Hypium：先核对和安装before、完成全部before用例终态，再按约定数据复位，核对和安装after并执行对应操作清单。单例业务失败、执行阻断和未执行分别记录；包级失败停止该比较阶段，不静默降级或回退target补造before。
- 采集按captureId登记实际截图、布局树、时间和哈希；完整解码并审计后才能用于业务证据。当前宿主按[视觉判定](runtime-visual-judgment.md)读取匹配图片，功能断言与视觉结论独立。
- 从结构化证据生成[测试报告](../../templates/upgrade-test-report.html)，逐原始行反查全部必测分支、用例、阶段结果和截图。任一必要分支缺少结果即不算该行完整覆盖；失败仍可属于已执行，前后共同失败可以可比但不算业务通过。

产物位于本批次evidence/runtime；每个run保留完整来源、路由、规格、用例、操作清单和包快照，不仅保存哈希。原始行分母不因缺工具、缺宿主、不可达或视觉失败而缩小。正常功能与官方变更触发结果分别说明，不宣称插桩代码覆盖率。

截图列由审计产物按sourceId+rowId投影到[行为结果表](../../templates/results.md#行为结果与可选测试截图)，不手工将首页或诊断图关联全部行。非视觉项允许实际返回/回调/日志证据，没有业务图时截图列留空；所选无需适配项仍测试正常功能。

仅修改后验证执行同样的功能取证但只测试 after，不伪造 before；不运行则不启动设备。代码/配置变化后重新构建 after 并重测受影响用例，before 归档不改、不回退工程补造。测试或设备失败保留可信修复，明确实际受阻阶段。跨系统范围按已有授权分别记录，见[target 升级兼容](../upgrade/upgrade-compatibility.md#记录与验证边界)，不将异系统运行称为有效 before/after 对比，不自动扩大最低设备任务。

## 清理与共享证据

失败先保存可取得的hilog、布局和截图，说明传输、安装、启动、进程稳定或业务断言哪个阶段受阻；不能凭shell echo成功断言HAP传输正常，进程未稳定不凭猜测归咎快照损坏。不原样重试相同确定性阻断。

先保存现场，再清理临时传输目录并停止本次新启动的模拟器，核对实际退出码和已停止状态；失败后不启动另一台。已有实例与真机不关闭，停止失败单独报告，不能覆盖功能事实。Windows PowerShell本地路径保持原生，HDC远端/data/local/tmp路径不做Windows转换，接收文件指定真实cwd和文件名，保留图片实际格式；shell echo成功不证明HAP传输成功；Git Bash仅为单条HDC设置必要MSYS_NO_PATHCONV，不永久改全局环境。


旧材料只读，不恢复旧执行器或继承旧通过。一次真实宿主用例可关联库与应用，但逐项说明当前库消费、原始行与实际功能证据；行为对比还须对应两个有效阶段。交付按所选主流程分别填写实际覆盖、功能、视觉及清理，行为另列有效对比，废弃不生成比较状态。
