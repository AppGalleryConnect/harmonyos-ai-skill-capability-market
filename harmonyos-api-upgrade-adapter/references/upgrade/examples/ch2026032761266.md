# CH2026032761266-Dialog、Toast、AlphabetIndexer和文本选择菜单默认开启沉浸式系统材质

## 来源与版本

身份：扫描Rule ID CH2026032761266。变更版本：26.0.0 Beta1。

[完整官方章节](../../changelogs/26.0.0/beta1-ux-style-and-effect-changes.md#dialogtoastalphabetindexer和文本选择菜单默认开启沉浸式系统材质)（起始行146）；[官网原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/changelogs-ux-7001#ch2026032761266)。接口起始版本、行为版本与target隔离分别核对，不相互替代。

## 旧新行为

target≥26.0.0时，指定Dialog、Toast、AlphabetIndexer和文本选择菜单默认开启沉浸式系统材质。变化的是已存在菜单/弹窗的默认材质，不意味着普通Text自动获得选择能力。

## 影响条件与工程核查

先核对准确SDK的API/重载、接收者、主题与完整样式。主动设置背景色、背景模糊、阴影或边框时，默认材质不会生效。Text另查copyOption及封装：准确SDK的普通Text默认CopyOptions.None；仅在确认未启用复制时可排除该调用的选择菜单材质场景，不能套到RichEditor或其他文本变化。

## 受影响与不受影响示例

未覆盖默认材质的真实弹窗/菜单需要评估视觉差异；已有背景等有效覆盖时无需为本条删除原样式。下面表示业务原本需要复制的Text，不是为了适配强制开启复制：

```ts
Text('允许复制的内容')
  .copyOption(CopyOptions.LocalDevice)
```

真实普通Text未写copyOption且封装未启用复制时可无需修改；已有选择能力的调用继续核对菜单样式。不能统一补None关闭原业务，InApp与LocalDevice范围也不能混用。

无样式Toast/AlertDialog已确认采用新材质时，不能仅以“视觉增强、不影响功能”统一判无需适配。默认保持旧体验，应列可选适配及局部方案成本交由spec确认；已明确接受后处理状态可为NO_CHANGE，但评估分类与接受依据保留，不冒充未触发。

## 最小方案与边界

局部问题优先评估准确SDK支持的局部参数；新增systemMaterial/uiMaterial能力需核对自身支持范围。只有业务明确要求应用级关闭时，才将以下metadata合并到现有entry模块module.json5：

```json
{
  "name": "ohos.arkui.UIMaterial.state",
  "value": "disable"
}
```

该开关影响整个应用，须纳入共享方案；不能为一个弹窗默认全局关闭，不覆盖其他metadata或整文件配置。不要把同名业务Dialog当SDK对象，也不要为启用新效果删除已有业务样式。

## 验证与证据缺口

弹窗确认/取消、显示/关闭、Toast内容及回调分别验证；Text检查长按、菜单、选择回调和剪贴板。核对原主题及授权设备效果，不能以取消成功证明确认回调正确。默认值、重载或样式覆盖不明时列具体缺口；截图Text本身或构建通过不证明菜单材质已验证。
