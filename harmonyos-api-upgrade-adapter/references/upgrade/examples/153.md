# 153-属性动画onFinish结束回调在UIAbility退后台时因有限循环动画被终止而提前触发

## 来源与版本

身份：扫描Rule ID `153`。

依据[官方完整章节](../../changelogs/5.0.1(13)/beta3-ux-style-and-effect-changes.md#属性动画onfinish结束回调在uiability退后台时因有限循环动画被终止而提前触发)（36–61行）。变更发布于5.0.1(13) Beta3，涉及AnimateParam和KeyframeAnimateParam的onFinish；原文没有target隔离说明，不能自造`target ≥ 13`分支。

本地API 26 SDK的`openharmony/ets/component/common.d.ts:3533–3591`明确iterations默认1、-1为无限、0不播放，onFinish会因UIAbility退后台终止有限动画而触发；`26241–26274`对KeyframeAnimateParam给出相应声明。章节起始API 7不表示KeyframeAnimateParam所有API均自7可用，后者本地声明自11起。

## 旧新行为

旧行为不感知UIAbility前后台，退后台后按原时长和次数走完再回调；新行为退后台时尚未结束的有限循环动画会停止至终点态并立即触发onFinish。无限循环动画不因这次退后台停止。

onFinish只能证明动画已结束，不能证明用户已观看完整时长或业务操作已完成。若回调只做可重复的视觉收尾，新时机可能可接受；若回调提交订单、奖励、开始倒计时、导航或释放仍在使用的资源，提前触发可能改变业务。高频指导里的“无需适配、不影响业务”不能覆盖具体回调。

## 影响条件与工程核查

定位`.animation(...)`、animateTo及关键帧调用传入的参数，追踪iterations默认值/动态值、onFinish函数引用和闭包捕获。确认在动画仍活跃时UIAbility确会退后台，而不是仅组件隐藏；记录UIAbility生命周期、动画启动/结束和业务状态的时间线。

阅读回调完整调用链，区分视觉状态落定、业务完成、用户观看时长、资源回收和页面导航。还要查异步任务或其他生命周期是否执行同一副作用，避免重复完成。证据包括参数实际值、未结束时退后台的操作、回调副作用及权威业务完成信号。

可排除无onFinish依赖、仅无限循环或不播放的分支；但仍须说明业务范围，不把所有属性动画一并标安全。只有函数名`onAnimationDone`，缺实现或iterations来源时属于证据不足。

## 受影响与不受影响示例

下面是传给属性动画的参数片段，`this.submitOrder()`是现有工程提交订单的方法；动画时长被业务当作确认等待期：

```ArkTS
{ duration: 1200, iterations: 2,
  onFinish: () => { this.submitOrder() } }
```

动画未结束时退后台会提前执行提交，因此受影响。不能据此把提交方法改名或只加“当前在前台”判断就认为已解决：被跳过的合法提交可能永远丢失。

不受影响例：`iterations: -1`的装饰性旋转，未使用onFinish推进业务；或有限动画onFinish仅将已确定完成的装饰遮罩标为隐藏，操作允许提前收尾且回调幂等，前后台回归通过。默认iterations省略仍是有限1次，不能遗漏。

## 最小方案与边界

把需要完整等待、异步完成或用户确认的业务决策移到对应的权威业务状态/完成事件，onFinish保留视觉收尾。时间约束应按真实时间契约处理，并在恢复前台时核对剩余状态；不能把延迟提交统一替换为定时器，因为后台调度和用户观看时间并不等价。

实际最小修改取决于现有状态机：记录动画终止与业务完成的区别，确保提交/导航只执行一次、取消路径仍有效。若业务就是动画到终点即可执行，则可保留实现并注明已接受提前完成。不要把有限动画改成无限循环以规避回调，不删除所有onFinish，不靠target分支回退。

## 验证与证据缺口

逐一覆盖正常完成、开始后立即退后台、中途退后台、已完成后退后台、多次前后台切换、取消/替换动画、页面销毁；记录回调时间、业务状态和副作用次数。确认恢复前台后视觉终点正确、必要业务未丢失或重复，并单独对照无限循环分支。

本案例真实编译、UIAbility生命周期操作、设备时间线和业务回归均未执行。若缺回调实现、业务完成契约或生命周期证据，不能写“onFinish不影响业务”，应记录证据不足及待补的调用链。
