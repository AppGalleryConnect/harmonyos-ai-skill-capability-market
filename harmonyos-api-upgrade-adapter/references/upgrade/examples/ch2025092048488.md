# CH2025092048488-Progress组件color属性设置渐变色规格变更

## 来源与版本

身份：扫描Rule ID `CH2025092048488`。

[完整官方章节](../../changelogs/6.1.0(23)/changes-for-all-apps.md#progress组件color属性设置渐变色规格变更)明确 targetSdkVersion≥6.1.0(23) 时生效，变更发布归属6.1.0(23)。本地标题映射确认扫描 RuleID 为 CH2025092048488；本机DevEco扫描规则资源 `HarmonyOS_6.1.0(23)_Beta1.json` 的interfaceChanges.sdkVersion标注为 `6.1.0(23) Beta1`。这是扫描规则的版本标签，与官方本地归档 `6.1.0(23)` 分别保留，不改写归档版本。Progress.color 起始 API Level7，与本次渐变行为门槛不同。

本机 SDK 26.0.0.105 Release 的 `ets/component/progress.d.ts` 声明 `color(value: ResourceColor | LinearGradient)`，注释说明 Ring 从API10支持渐变，Linear/Capsule 从API23支持；`data_panel.d.ts` 声明 `new LinearGradient(ColorStop[])`，ColorStop.color 为 ResourceColor、offset 为 Length。枚举真实拼写为 ProgressType.Linear / Capsule / Ring。

## 旧新行为

Linear、Capsule 类型通过 color 传 LinearGradient 时，旧行为显示默认主题色，新行为显示指定渐变。纯色 ResourceColor、未设置color及Ring已有渐变能力不属于本条新增范围。不要将 `.linearGradient(...)` 通用背景属性或“颜色数组”文本命中等同于 Progress.color 的 LinearGradient 入参。

## 影响条件与工程核查

沿 Progress 类型、完整属性链和共享样式追踪最终 color，核对返回值真实类型、主题/资源/状态分支和业务颜色要求。确认是否原本有意依赖“不生效后回落主题色”，以及实际使用的主题色；旧默认不一定等于固定蓝色，禁止硬编码一个示例色替代全应用主题。

新渐变正是业务预期时可以保留原代码并说明新行为；只有需要保留旧单色视觉时提出局部改为准确纯色资源的方案。已用 ResourceColor、固定 Ring 或未到 target 门槛可说明排除依据；动态类型/返回值未给出时保留缺口。

## 受影响与不受影响示例

下面展示 Linear/Capsule 的color渐变入参，色标结构已由准确SDK核对；示例值不作为统一配色：

```ts
// 页面字段
private gradient: LinearGradient = new LinearGradient([
  { color: '#E5B87B', offset: 0.5 },
  { color: '#E05F2A', offset: 1.0 }
])
// build内原属性链
Progress({ value: 70, total: 100, type: ProgressType.Linear })
  .color(this.gradient)
```

需要保持旧主题单色且已核实原主题颜色资源时，仅将本调用改用该 ResourceColor。`Progress({ value: 70, type: ProgressType.Linear }).color(Color.Grey)` 本条无需修改；Ring 的 LinearGradient 也不能因此转成单色。

## 最小方案与边界

按业务分别保留渐变或使用准确的单色资源，不批量删 color、不强制增加渐变、不更换进度条类型。不为本条修改进度值/动画/状态管理。若旧主题色、暗色资源或动态主题缺失，应先补颜色证据，不能用Color.Blue宣称恢复原主题。

本次 target 隔离与 LinearGradient 的接口可用性分开分析；跨系统上同一渐变在旧运行环境可能仍回落主题色，需按实际发布组合验证，不能以目标SDK支持声明证明设备视觉一致。

## 验证与证据缺口

比较原包/最终包中实际命中的Linear/Capsule，覆盖0/中间/满进度、明暗主题与颜色分支；纯色和Ring作对照。记录旧主题颜色与新渐变截图，构建只证明类型兼容。真实编译、设备运行、截图均未执行。
