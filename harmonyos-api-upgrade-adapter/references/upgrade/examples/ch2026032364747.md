# CH2026032364747-List组件onScrollVisibleContentChange事件行为变更

## 来源与版本

身份：扫描Rule ID `CH2026032364747`。

[完整官方章节](../../changelogs/26.0.0/beta2-changes-for-all-apps.md#list组件onscrollvisiblecontentchange事件行为变更)位于 26.0.0 Beta2，明确 targetSdkVersion≥26.0.0 时生效，并记载从 OpenHarmony SDK 7.0.0.28 开始发生。事件起始 API Level 为12，不能用12替代本次变更门槛。扫描 RuleID 为 CH2026032364747；本地标题映射未收录，已从 DevEco 规则包核实扫描身份。

本机 SDK 26.0.0.105 Release 的 `ets/component/list.d.ts` 声明回调 `(start: VisibleListContentInfo, end: VisibleListContentInfo) => void`；index 为 number，itemGroupArea 和 itemIndexInGroup 都可选。事件及参数接口 since12。声明不是“每次清空都会触发任意事件”的证明。

## 旧新行为

仅针对 List 从有子组件切换为无子组件时本事件上报的参数：旧行为复用原 start/end，新行为两者 index 均为 -1，itemGroupArea 和 itemIndexInGroup 均为 undefined。不能只处理 index 而继续把组内字段当作有效值，也不能将本条扩展为任意滚动回调或所有初始空列表时序变化。

## 影响条件与工程核查

核查真实 target、List 的数据来源和渲染分支，确认可以从有子组件变成没有子组件。数据数组为空不必然等于 List 无子组件：还要检查固定 ListItem、占位项、ListItemGroup 及封装。沿回调追踪索引的数组访问、曝光/选中/区间缓存、分组字段读取及调用下游，核对已有 -1 和 undefined 处理。

无清空路径、回调不依赖该参数，或已正确处理空列表参数且业务状态一致时无需修改。只命中回调名、缺失渲染代码或下游实现时不能直接判定。运行在旧系统的新 target 包及原包要按真实组合取证。

## 受影响与不受影响示例

应用清空全部 List 子组件后，直接用 `this.items[start.index]` 访问数据并读取其 id，新参数会使访问越界。适配先处理空范围；下面仅是已有 List 回调的片段，`clearVisibleRange()` 与 `updateVisibleRange()` 代表工程原有业务方法：

```ts
.onScrollVisibleContentChange((start, end) => {
  if (start.index === -1 && end.index === -1) {
    this.clearVisibleRange()
    return
  }
  this.updateVisibleRange(start, end)
})
```

非空路径仍需遵守 index 和可选分组字段语义。若原回调已经清除空范围并在非空分支读取可选字段前检查，则无需重复加保护或改用其他滚动事件。

## 最小方案与边界

只在受影响回调增加明确的空范围分支，使选中/曝光缓存按原业务清空或保留；已有数据源空态处理可复用，但不能把 -1 夹成0、替换成旧索引或伪造组索引，这会把空列表算作真实可见项。itemGroupArea/itemIndexInGroup 为 undefined 时不得用非空断言掩盖。

需要同时维持旧系统行为时，结合数据源和真实回调时序核查旧系统复用索引的路径，不能声称一个新参数判断已证明全部历史组合正确；也不为本条删除 onScrollVisibleContentChange 或改掉列表结构。

## 验证与证据缺口

验证有内容→全部删除→重新填充，检查 start/end 的三个成员、空范围状态、无越界/无虚假曝光；有分组时覆盖组头尾与组内索引，保留非空滚动对照。真实编译、事件日志与设备用例均未执行，不将静态类型正确写成回调时序已验证。
