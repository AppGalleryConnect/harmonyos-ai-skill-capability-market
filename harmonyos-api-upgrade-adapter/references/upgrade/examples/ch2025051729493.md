# CH2025051729493-禁止在转场动画过程中，更新消失节点的属性。

## 来源与版本

身份：扫描Rule ID CH2025051729493。变更版本：5.0.1(13) Beta3。

[完整官方章节](../../changelogs/5.0.1(13)/beta3-os-api-behavior-changes.md#禁止在转场动画过程中更新消失节点的属性)（起始行183）；[官网原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-releases/changelogs-for-all-apps-b106#禁止在转场动画过程中更新消失节点的属性)。接口起始版本、行为版本与target隔离分别核对，不相互替代。

## 旧新行为

target≥5.0.1(13)时，正在消失的节点不再响应该转场阶段的属性更新；不能把出现节点或稳定在树节点的属性更新当作同一变化。

## 影响条件与工程核查

核对条件渲染/列表删除、数据销毁、属性状态与转场的实际顺序，识别更新对象是否已经进入消失阶段；只看同一闭包的代码顺序不能证明渲染先后。

## 受影响与不受影响示例

受影响：开始消失后仍期望修改该节点颜色等属性；仅更新出现节点或未退出节点时可按实际条件无需修改。状态刷新/脱树时机未知时保留具体缺口，不用固定延时猜测。

## 最小方案与边界

业务要求先变色再退出时，以下为已有状态方法中的关键片段，仍须核对刷新与脱树顺序：

```ts
// this.isVisible、this.textColor 是组件已有状态。
this.getUIContext().animateTo({}, () => {
  this.textColor = Color.Blue;
});
this.getUIContext().animateTo({}, () => {
  this.isVisible = false;
});
```

不要只颠倒同一闭包两行就认定已渲染，也不要额外用setTimeout。删除数据时保留转场节点仍需的有效内容，不能因节点未销毁而访问已清空对象。

## 验证与证据缺口

覆盖快速切换、ForEach删除及不同转场，分别核对业务状态和消失过程；保留初始化、数据有效期与回调顺序的证据。未运行时不把静态代码顺序当作设备通过。
